# 分支说明：UKB 知识库 / 证据系统 v3 / 一致性校核（2026-11-03）

> 分支：`feat/ukb-evidence-v3-design-review`，基线 `main@c40deb2`。
> 本文件描述本分支相对基线的源码改动、验证范围与已知边界，供评审与后续维护使用。

## 1. 三个功能模块

### 1.1 通用知识库 UKB（`ukb/`、`evolution/kb/`）

新增 `ukb/` 独立包（冻结 1.0.0，含 `RELEASE.json` 逐文件 sha256），只用 Python 标准库 + SQLite：

- **唯一写路**：`propose → AI 预审（prereview）→ 管理员哈希绑定批准（decide）`；MCP 通道不接受管理员决定。
- **注册表驱动**：类型、分类面、标签、条件键、关系、来源类型、消费口径、高危规则、文件格式/角色、设置共 12 类注册表，扩展不需要改表结构。
- **逐级暴露检索**：`overview`（逐层标签）→ `catalog`（只给标题，超限提示细分标签）→ `read`（只能读本会话目录列出的条目，每次至多 3 条）。
- **文档型条目**：摘要层 + 原文层（按章节/页/行读取）、`checkout` 复用文件并附 provenance。
- **与 MDagent 的兼容层** `evolution/kb/adapter.py`：旧知识入口全部保留原签名与返回形状，`raw_json` 保真，`legacy_id` 反查；`MDAGENT_KB=ukb|legacy` 显式开关，未知值 fail-closed。
- **证据耦合**：`evidence_claim` 候选发布、原始来源健康检查、WAL 拒绝（要求 rollback-journal）、运行知识快照绑定。
- **统一接口** `evolution/kb/client.py`：`KnowledgeBase` 覆盖读/写/审核/状态/标签/注册表/文档/备份/健康/历史；`KBError` 带稳定错误码；写入只走 UKB API，不提供直接 SQL 写接口。
- **维护工具** `tools/kb/`：`bootstrap`（建库与管理员）、`import_legacy`、`verify_import`、`compare_modes`、`activate`、`prereview`、`review_queue`、`serve`、`pull_server_atoms`、`ensure_evidence`。

### 1.2 证据系统 v3（`evolution/evidence_v3/`、`mcp/evidence_*.py`）

把证据从"执行了"推进到"做得对"，并保持 fail-closed：

- **开放核查工作流**：`recognize → retrieve → propose(discover) → init → plan → evidence/measure → review → evaluate → advance → complete`，另有 `authorize/finish/reconcile_start` 执行许可链。
- **证据与授权分离**：`authorize` 只签发当前输入、当前阶段的单次动作许可；证据记录不能当执行许可使用。
- **状态机与并发**：每次状态变更需 `expected_revision`（可选 `expected_state_seq`），请求幂等（`request_id` 重放），任务级 + 代次级文件锁，`tmp + os.replace` 整写，备份 `O_EXCL`。
- **不可变工件**：证据、测量、审查、授权、运行等工件写入后校验哈希，篡改报 `ARTIFACT_MISMATCH`。
- **知识变化重验**：任务创建时绑定 `knowledge_snapshot`；UKB 变更后 `evaluate` 返回 BLOCK（`REVALIDATION_REQUIRED`），必须 `refresh_knowledge` 并重新审查才能继续。
- **执行桥**（`mcp/evidence_bridge.py`）：进程树超时终止、清理有独立宽限期、审计 JSON 不完整不得当成功、超时永不产生完成回执。
- **MCP 入口** `sim_evidence`：28 个 action 与 `evidence_api.dispatch` 一一对应；16 个工具无重名。
- **Web UI**（`webui/`）：本地 stdlib 服务，执行默认关闭，只转发公共 action；CSRF/Origin/CAS 校验。

### 1.3 一致性校核（`design-review-layer/`）

只读消费 MDagent 工件（intent.json / in.case / validate），不修改 MDagent 源码：

- **一致性引擎** `review_layer/consistency.py`：五档判定（`ok / questionable / unproven / invalid / plan_conflict`），检查 9–10 项：
  1. 系综（声明 vs 积分 fix；NPT 目标缺失→invalid，声明过期→plan_conflict）
  2. 时间步（支持 `variable` 链解析）
  3. 步数（`run` 合计）
  4. units
  5. pair_style
  6. 势函数（`key_params.forcefield.preferred` vs `pair_coeff` 实际文件）
  7. 温度（各阶段 `T_K` vs 积分 fix 的 `temp`）
  8. 加载速率（`cross_scale.loading` 数值 vs `fix deform erate`，ps⁻¹→s⁻¹，20% 容差；应力控制/速度控制分别核对）
  9. 观测量（`target_property` vs 脚本输出线索）
  10. 命令用途（数据文件 `rules/infile_rules.json` 驱动的实验类型白名单）
- **零规则审核层** `review_layer/review.py`：按所有者指示不注入任何政策规则，只汇总为 PASS / REVIEW / NEEDS_REVISION / FAIL，`findings` 恒为空。
- **UKB 读取** `review_layer/ukb_store.py`：基线维度（rule 9）、常见问题（lesson 12）、开放审查点（observation 25）；`load_common_issues()` 显式解析 `处置/类别/证据等级/状态`，未知处置保守取 `open`；`REVIEW_KB=legacy` 回退本地 JSON。
- **交互页** `web/design-plan.html`（模板 v1.3 冻结，sha256 校验）：方案全文 / 方案对照 / in 文件查验三段，外加审查点发现卡片与 UKB 检索调试抽屉；`/api/{cases,plan,infile,infile_check,discovery,ukb/debug}`。
- **报告与工具**：`cli.py` 生成 JSON/MD/HTML；`audit_report.py`、`discovery_report.py`、`export_bundle.py` 均为显式运行（有 `main()` 守卫），import 无副作用。

## 6. 已知边界（不宣称产品验收）

- 真实模型审阅需沿用 `model_research` 提供方配置；本机未配置凭证，`recognize` 明确 fail-closed。
- 真实求解器执行需服务器端已核验的执行适配配置；默认返回 `unsupported-action`，不静默回退。
- 一致性校核的 PASS 仅代表 intent 字段与 in 文件实现在检查项上一致，不代表物理结论成立；审核层零规则是所有者既定边界。
- `review_layer/sources.py` 的经验/证据源仍为 Null（接口占位）。
- Windows 上 `chmod 0600` 对令牌文件不生效，部署时需用 ACL 收紧。
- `test_evidence_v3_bridge` 的进程树超时用例对机器负载敏感，高负载下可能报 `bridge-termination-unknown`；空载 9/9 通过。
