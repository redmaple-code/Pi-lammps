## 0. 结论：要修的不是"证据规则"，是"接线与可见性"

代码级探针确认了两处独立断点，任何一处都足以让写路径永久失效：

1. `mcp/md_mcp.py:796` 的 `sim_evidence` 调 `evidence_api.dispatch()` 时**没有传 `human_verifier`**。`service.record_authorization` 第一句就是缺少它即 `HUMAN_AUTHORITY_REQUIRED`。所以通过 MCP 工具面**永远产生不了生产许可**。
2. `mcp/md_config.json` **没有 `evidence_execution_registrations`**，`configured_action_adapter` 返回 `UnsupportedExecutionAdapter`。即便手工写入许可，`start` 也直接 `AttributeError: 'UnsupportedExecutionAdapter' object has no attribute 'handoff'`。且 `scripts/install_config.py` 不播种该键，`md_config.json.example` 也没有——新装部署从构造上不可执行。

第三处是可见性：`handle()` 只在未知工具和未捕获异常时设 `isError`，所有业务失败（含 `execution-permit-required`、`HUMAN_AUTHORITY_REQUIRED`、`PIPELINE_ERROR`）都以普通结果返回。agent 看到的是"成功返回了一段内容"。

因此本方案按"先让失败可见 → 再让写路径可达 → 最后补可用性"排序，**不改证据规则本身**（E1–E5、风险门槛、证据分级、人工授权语义全部保持）。

## 2. FIX-1：MCP 接入人工核验通道

### 2.1 设计

人工授权必须由所有者**在带外**回答，agent 只能发起请求。复用现有"请求文件 → 决定文件"的审批习惯（参考 `dashboard/web_monitor.py` 的 `EXEC_GATE_DIR` 协议），但独立到证据授权专用目录，避免与执行闸卡混用。

```
<data_root>/human_inbox/
  requests/<request_hash>.json      # 服务端落盘，agent 可触发但不可授权
  decisions/<request_hash>.json     # 仅所有者 CLI 写入
  consumed.jsonl                    # 审计用（不参与放行判定）
```

判定规则全部 fail-closed：文件不存在、字段多/少、`decision != approve`、`request_hash` 不匹配、`task_id` 不匹配、超过 900 秒、签名不符 → 一律返回 `None`，服务随即抛 `HUMAN_AUTHORITY_REQUIRED`。

单次使用由两处保证，不靠消费记录：
- `request_hash` 绑定了 `subject_hash`/`spec_hash`，换输入即失效；
- `service.record_authorization` 对同一 `id` 写不可变工件，重复提交抛 `IMMUTABLE_ARTIFACT`；许可本身在 `start` 后 `PERMIT_CONSUMED`。

**信任边界（必须写进文档）**：单用户 Windows 上 agent 与 MCP 同用户，可写同一文件系统，所以这套通道是**可用性闸，不是安全边界**。若设置了 `MDSIM_HUMAN_INBOX_SECRET`，决定文件必须带 HMAC-SHA256 签名，秘密只存在于所有者自己的 shell 环境；生产部署应改用 OS 用户隔离（MCP 服务账号不可写所有者 inbox）或独立审批服务。

### 2.2 新增 `mcp/human_authority.py`

```python
"""Out-of-band human authority for evidence v3.

The MCP surface may ask for an authorization but can never grant one. Requests
are parked as data files; the owner answers them out of band through
``tools/human_approve.py``. Only a matching, unexpired, task-bound approval is
accepted; the service's immutable authorization record makes it single-use.
"""
import hashlib
import hmac
import json
import os
import re
import time
from pathlib import Path

MAX_AGE_SEC = 900
_ACTOR_RE = re.compile(r"^[A-Za-z0-9._@-]{1,64}$")
_DECISION_KEYS = {"schema", "kind", "request_hash", "task_id", "decision",
                  "actor_id", "reason", "issued_at"}


def inbox_root():
    from paths import data_root
    base = os.environ.get("MDSIM_HUMAN_INBOX") or os.path.join(data_root(), "human_inbox")
    return Path(base)


def _atomic_json(path, value):
    path.parent.mkdir(parents=True, exist_ok=True)
    tmp = path.with_name(path.name + ".tmp-%d" % os.getpid())
    with open(tmp, "w", encoding="utf-8", newline="\n") as stream:
        json.dump(value, stream, ensure_ascii=False, sort_keys=True)
        stream.write("\n")
    os.replace(tmp, path)


def _read_json(path):
    with open(path, encoding="utf-8") as stream:
        return json.load(stream)


def secret():
    value = os.environ.get("MDSIM_HUMAN_INBOX_SECRET", "")
    return value.encode("utf-8") if value else None


def sign(decision):
    key = secret()
    if key is None:
        return None
    body = json.dumps({k: v for k, v in decision.items() if k != "signature"},
                      ensure_ascii=False, sort_keys=True, separators=(",", ":")).encode("utf-8")
    return hmac.new(key, body, hashlib.sha256).hexdigest()


def park(task_id, request, context):
    """Park a pending owner decision. Parking is not authority."""
    from evidence_v3.contracts import canonical_hash
    request_hash = canonical_hash(request)
    path = inbox_root() / "requests" / (request_hash + ".json")
    if path.exists():
        return path
    _atomic_json(path, {"schema": 1, "kind": "mdagent-authorization-request",
                        "request_hash": request_hash, "task_id": task_id,
                        "request": request, "context": context,
                        "parked_at": int(time.time())})
    return path


def pending(task_id=None):
    rows = []
    for path in sorted((inbox_root() / "requests").glob("*.json")):
        try:
            row = _read_json(path)
        except (OSError, ValueError):
            continue
        if task_id and row.get("task_id") != task_id:
            continue
        rows.append(row)
    rows.sort(key=lambda row: row.get("parked_at", 0), reverse=True)
    return rows


def verify(task_id, request, context):
    """Return a trusted-human-event attestation, or None. Never invent authority."""
    from evidence_v3.contracts import canonical_hash
    request_hash = canonical_hash(request)
    path = inbox_root() / "decisions" / (request_hash + ".json")
    if not path.is_file():
        park(task_id, request, context)
        return None
    try:
        decision = _read_json(path)
    except (OSError, ValueError):
        return None
    expected = set(_DECISION_KEYS) | ({"signature"} if secret() else set())
    if set(decision) != expected:
        return None
    if (decision.get("kind") != "mdagent-authorization-decision" or
            decision.get("request_hash") != request_hash or
            decision.get("task_id") != task_id or
            decision.get("decision") != "approve"):
        return None
    actor = decision.get("actor_id")
    if not isinstance(actor, str) or not _ACTOR_RE.match(actor):
        return None
    issued = decision.get("issued_at")
    if type(issued) is not int or abs(time.time() - issued) > MAX_AGE_SEC:
        return None
    if not isinstance(decision.get("reason"), str) or not decision["reason"].strip():
        return None
    if secret() and not hmac.compare_digest(str(decision.get("signature")), str(sign(decision))):
        return None
    source_id = "human-inbox:" + request_hash
    return {"actor_id": actor, "source_refs": [source_id],
            "authorization_source": {"kind": "trusted_human_event",
                                     "source_id": source_id, "actor_id": actor,
                                     "request_hash": request_hash, "verified": True}}
```

### 2.3 新增 `tools/human_approve.py`

```python
#!/usr/bin/env python3
"""Owner-side CLI for evidence v3 authorizations. Never call this from the agent."""
import argparse
import json
import sys
import time
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1] / "mcp"))
import human_authority as human  # noqa: E402


def main(argv=None):
    parser = argparse.ArgumentParser(prog="human_approve")
    sub = parser.add_subparsers(dest="command", required=True)
    row = sub.add_parser("pending"); row.add_argument("--task")
    row = sub.add_parser("show"); row.add_argument("request_hash")
    for name in ("approve", "reject"):
        row = sub.add_parser(name)
        row.add_argument("request_hash")
        row.add_argument("--actor", required=True)
        row.add_argument("--reason", required=True)
    args = parser.parse_args(argv)

    if args.command == "pending":
        for item in human.pending(args.task):
            request = item["request"]
            print(item["request_hash"], item["task_id"], request.get("scope"), request.get("reason"))
        return 0

    path = human.inbox_root() / "requests" / (args.request_hash + ".json")
    if not path.is_file():
        print("no such request: %s" % args.request_hash, file=sys.stderr)
        return 2
    request_file = human._read_json(path)
    if args.command == "show":
        print(json.dumps(request_file, ensure_ascii=False, indent=2))
        return 0

    decision = {"schema": 1, "kind": "mdagent-authorization-decision",
                "request_hash": args.request_hash, "task_id": request_file["task_id"],
                "decision": "approve" if args.command == "approve" else "deny",
                "actor_id": args.actor, "reason": args.reason, "issued_at": int(time.time())}
    signature = human.sign(decision)
    if signature:
        decision["signature"] = signature
    human._atomic_json(human.inbox_root() / "decisions" / (args.request_hash + ".json"), decision)
    print(args.command, args.request_hash)
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

### 2.5 正确使用顺序（写进工具描述与文档）

```
init → plan → review（模型审阅）→ evaluate → advance
     → authorization（返回 HUMAN_AUTHORITY_REQUIRED + pending_request）
     → 所有者执行 human_approve.py approve
     → authorization（重放同一参数，取得 authorization 记录）
     → authorize（签发 permit，内部做一次版本探针）
     → sim_exec(start) → finish → measure → evaluate → complete
```

注意：`authorize(kind=production)` 要求任务已在 `EXEC` 阶段且 `dependencies.cwd/inputs` 与 spec 完全一致；`kind=validation` 要求存在 `review` 记录的 `authorization_refs`。两条路径都需要人工授权，这是设计意图，不是缺陷。

_ERROR_STATUSES = {"PIPELINE_ERROR", "RESEARCH_ERROR", "KIT_UNAVAILABLE", "NO_LOG"}

- 这条只影响"研究类工具不可用"的解释，不改变 fail-closed：无来源仍不得给出 verified 结论。

### 6.4 清理死入口

`md_mcp._exec_gate_check` 已无调用点且无条件返回拒绝。删除该函数，避免后续误以为旧 `cmd` 通道还在。旧通道的关闭由 schema + handler 四参校验承担，语义不变。

## 7. FIX-6：审批卡"查询即消费"

缺陷在 `sim-agent-runtime/packages/dashboard/server.mjs:260`：`/api/exec_gate_lookup` 在返回前直接 `gateConsume(root, cmd)`。任何一次查询（包括自查、重发前的确认）都会烧掉唯一一张卡。

改法：

```js
if (u.pathname === '/api/exec_gate_lookup') {
  ...
  const r = gateLookup(root, cmd);       // 纯读，不消费
  return send(200, r);
}
if (u.pathname === '/api/exec_gate_consume' && req.method === 'POST') {
  // 由真正执行的一侧在"白名单/cwd/哈希校验通过且已启动"后调用
  ...
}
```

配套约定：
- kit 侧先做白名单与路径校验，再调用 consume；校验失败不得消费。
- `dsh-plugins/dsh-md-ops-gate` 保持 lookup-only。
- 插件默认 gated 工具名是 `mcp__mdsim__sim_exec`，而本机 profile 的 `serverName` 是 `mdagent`（实际工具名 `mcp__mdagent__sim_exec`）。二者要么统一（改默认或显式配置 `tools`），要么明确不启用该插件；**不能保持"装了但永不命中"的中间态**。
- 无 UI 时返回明确原因：`approval-ui-unavailable`，不要只给通用 fail-closed。

补充 node 测试：连续两次 lookup 都必须返回 `approved_unconsumed: true`；consume 后一次返回 false。

## 8. FIX-7：压缩双计

根因已定位在 `dsh-llm-pi-ai` 的 `mapUsage`（`lib/index.js:413-421`）：`inputTokens: usage.input` 没有减去 `usage.cacheRead`，而中转站按 OpenAI 口径返回的 `input_tokens` 已含缓存，`token-meter` 再按互斥桶相加即双计。

修复（框架包补丁，升级会覆盖，需固化到部署脚本）：

```js
// before
inputTokens: usage.input
// after
inputTokens: Math.max(0, (usage.input ?? 0) - (usage.cacheRead ?? 0))
```

配套：
- `scripts/patch_dsh_usage.mjs`：定位 `profiles/*/node_modules/@deepseek-ai/dsh-llm-pi-ai/lib/index.js`，备份为 `.bak-<date>`，幂等替换，打印命中位置。
- `scripts/verify_usage_caliber.py`：同一段固定 prompt 连发两次，断言第二次 `cache_read > 0` 且 `input_tokens` 与第一次相同（证明端点口径），再用会话日志校验"相邻步提示词负增量应为 0"。
- profile 仍保留 `maxTokens: 16384` 作为兜底；注释注明这是治标。

## 12. 风险与待拍板

1. **信任边界**：单用户本机上 `human_inbox` 对 agent 可写，本方案只提供"人类确认"的可用性语义。若要求真实防伪造，必须 OS 用户隔离或外部审批服务 + HMAC 秘密不入 agent 环境。**待所有者决定采用哪一档**。
2. **入口文件名约定**：注册表要求精确文件名，统一为 `in.production`/`in.validation` 会与历史案例目录不一致。备选：为每个案例由所有者运行登记脚本追加注册（更严格但更繁琐）。
3. **kit 缺件**：没有 `agent_deploy_kit` 时写门按设计不可用。本方案不会伪造执行能力；是否允许提供一个显式 `MDSIM_EXEC_BRIDGE=dev` 的本地桥（带白名单+审计日志+醒目警告）作为开发便利，**需所有者拍板**（默认不提供）。
4. **外部仓库改动**：FIX-6/FIX-7 分别在 `sim-agent-runtime` 与 dsh 框架包内，本工作区只能提供补丁与验收脚本，需在对应仓库登记 issue。
5. **`isError` 行为变化**：agent 会在更多场景停下并报告，而不是继续试错。这是本次修复的目标，但会改变现有会话的"成功率"统计口径，需在验收文档注明。
