# 开发：知识库统一接口层与维护命令 v1.0

> 日期：2026-11-02。状态：**已实施并验证**（T-071 / EV-20261102-005）。
> 适用：后续所有需要读写 UKB 的功能块（审核台、迁移、统计、批量维护、证据/经验写入）。
> 原则：一个知识库、只走 UKB API、写入必须经过审核链、不新增知识存储、不直写 SQL。

## 1. 入口

| 文件 | 作用 |
|---|---|
| `MDagent-evidence-v3/evolution/kb/client.py` | **主接口**：面向所有功能块的 `KnowledgeBase` 类、`KBError`、令牌与根解析、`ensure_admin_token`/`ensure_system_admin` |
| `design-review-layer/review_layer/kb_api.py` | 兼容转发：把 `evolution.kb.client` 的 `KnowledgeBase`/`KBError` 暴露给校核层旧代码 |
| `design-review-layer/review_layer/ukb_store.py` | 一致性校核专用桥接 + 维护函数（元数据回填、seed、连接管理） |
| `design-review-layer/review_layer/ukb_cli.py` | 维护与查看命令：`inspect` / `list` / `find` / `show` / `ensure-admin` / `ensure-system` / `upgrade-metadata` / `seed-all` / `stats` / `baseline` / `common` |
| `MDagent-evidence-v3/tests/test_kb_client.py` | 通用客户端回归（5 项） |
| `design-review-layer/tests/test_kb_api.py` | 校核层兼容接口回归（13 项） |

`client.py` 不包含任何域规则；它只暴露 UKB 的通用概念（entry/revision/tag/source/condition/review task/registry）。

## 2. 基本用法

其他模块（dashboard、webui、`tools/kb`、`evolution` 内新功能）直接使用知识库模块：

```python
from evolution.kb.client import KnowledgeBase, KBError
```

校核层旧代码可继续 `from review_layer.kb_api import KnowledgeBase, KBError`（兼容转发）。

```python
with KnowledgeBase() as kb:
    # 读：目录只给标题，read 才给全文；read 一次至多 3 条（agent 口径）
    cat = kb.catalog(scope={"topic": ["general"]}, types=["lesson"])
    entry = kb.entry(cat["items"][0]["ref"])

    # 写：propose ->（可选预审）-> 管理员决定；默认不自动批准
    task = kb.revise(entry["ref"], fields={"risk": "..."}, note="修订理由")
    kb.mechanical_prereview(task["task_id"])
    kb.decide(task["task_id"], "approve", "本地维护批准")

    # 状态/标签同样走审核
    kb.change_status(entry["ref"], "deprecated", "原因", approve=True)
    kb.add_tags(entry["ref"], [{"facet": "stage", "tag": "planning"}], "原因", approve=True)
```

`KnowledgeBase(root=..., admin=..., token=..., profile="agent", submitter="kb-api")`：
- `root` 默认取 `REVIEW_UKB_ROOT`，否则仓库 `data/ukb`。
- `admin/token` 默认读 `MDAGENT_UKB_ADMIN_FILE` / `REVIEW_UKB_ADMIN_FILE`，否则 `design-review-layer/ukb_admin.json`（0600）。
- `profile` 决定读可见范围：`agent`（active/trial）、`reviewer`（全部状态）。
- 每个进程/线程建议各自持有一个 `KnowledgeBase`；不要把同一个 SQLite 连接跨线程共享。

CLI 查看：

```bash
python -m review_layer.ukb_cli inspect                 # 状态/计数/完整性/审计
python -m review_layer.ukb_cli list --type lesson      # 管理员视角列表
python -m review_layer.ukb_cli find CI-008 --type lesson
python -m review_layer.ukb_cli show e1a196ff524cbdb6fc@2
```

## 3. 接口清单

### 3.1 读与检查

| 方法 | 说明 |
|---|---|
| `status()` / `stats()` | 条目状态计数、按类型/状态分组 |
| `integrity()` | `PRAGMA integrity_check/quick_check/foreign_key_check`、journal mode |
| `verify_audit()` | 审计哈希链校验 |
| `audit_tail(limit)` | 最近审计事件（只读 SQL） |
| `schema()` | 表与列清单（只读 SQL，供维护工具使用） |
| `revisions(entry_id)` | 某条目的全部修订（含旧版本） |
| `profiles()` / `types()` / `type_spec(type_id)` | 消费口径、类型注册表与字段规范 |
| `facets()` / `tags(facet)` / `condition_keys()` / `source_types()` | 扩展注册表 |
| `overview()` / `catalog()` / `read()` / `entry()` | 逐级暴露读；`entry()` 单条全文 |
| `list_entries(types, statuses)` | 管理员视角的最新修订列表 |
| `find_entries(title_contains, type_id)` | 标题包含查询（确定性，不做语义检索） |
| `entry_by_title()` | 精确/近似标题定位 |
| `read_original()` / `checkout()` | 文档型条目的原文读取与文件复用 |

### 3.2 写与审核

| 方法 | 说明 |
|---|---|
| `propose(payload)` | 提交 `new/revise/reinforce`，返回 `task_id`；默认 `channel=cli` |
| `mechanical_prereview(task_id)` | 结构预审（只检查结构，不做语义判断），用于本地 seed/测试 |
| `prereview(task_id, opinion)` | 提交完整 AI 预审意见（调用方自行判断内容） |
| `decide(task_id, decision, rationale)` | 管理员决定；支持 `approve/approve_as_trial/request_changes/reject/correct/reinforce_into` |
| `propose_and_approve(payload)` | propose + 结构预审 + approve，仅用于受信本地维护 |
| `revise(ref, fields/title/tags/sources/conditions, note, approve)` | 基于当前修订生成完整 revise payload；`fields` 合并，值为 `None` 表示删除 |
| `change_status(ref, status, reason, approve)` | 状态变更；`allowed_transitions(ref)` 给出合法目标 |
| `add_tags()` / `drop_tags()` | 标签增删；必需 facet 缺标签会被拒绝（`TAG_REQUIRED`） |
| `propose_registry(kind, spec, reason, approve)` | 扩展类型/标签/条件键/来源类型/口径等注册表 |
| `feedback(ref, outcome, note)` | 记录使用反馈 |

### 3.3 维护

| 方法 | 说明 |
|---|---|
| `backup(dest)` / `export(dest_dir)` | SQLite 备份 / UKB 导出 |
| `ukb_store.ensure_admin_token(admin_id, force)` | 校验并（必要时）轮换人类管理员 token，写入 0600 文件，不打印 |
| `ukb_store.ensure_system_admin()` | 创建/校验 `mdagent-system`，写 `system_auto.token`（机器观察自动入库） |
| `ukb_store.upgrade_common_issue_metadata()` | 把 category/disposition/evidence_level/status 回填到 lesson 的 `situation` |
| `ukb_store.seed_baseline/seed_common_issues/seed_discovery` | 幂等 seed（标题已存在则跳过） |
| `ukb_store.close_connections()` | 关闭模块缓存的连接（Windows 下释放文件锁） |

## 4. 数据模型与写入纪律

- `entry`：稳定身份、类型、状态、当前 `head_rev`。
- `entry_revision`：不可变修订（标题、fields_json、content_hash、parent_rev、change_note）。
- `entry_tag` / `entry_source` / `entry_condition`：按修订绑定。
- `review_task` / `review_decision` / `rev_approval`：审核任务、预审/管理员决定、批准回执。
- `audit_log`：哈希链审计。
- 写入顺序固定为 `propose -> prereview -> decide`；`candidate` 对 agent 不可见，批准后才有 `head_rev`。
- 不提供直接 SQL 写入接口；维护查询只允许 `SELECT`/`PRAGMA`。
- 状态转换（UKB 内置）：`active -> deprecated/superseded/revoked`、`trial -> active/deprecated/revoked`、`deprecated -> active/revoked`。`active` 不能直接转 `trial`。
- 必需 facet（当前 `topic`）在批准时不能为空；删标签前先确认替代标签。

## 5. 环境与令牌

| 变量/文件 | 说明 |
|---|---|
| `REVIEW_UKB_ROOT` | 一致性校核/接口层使用的 UKB 根；默认 `MDagent-evidence-v3/data/ukb` |
| `MDAGENT_UKB_ADMIN_FILE` / `REVIEW_UKB_ADMIN_FILE` | 人类管理员 token 文件（前者优先）；默认 `design-review-layer/ukb_admin.json`；测试必须覆盖 |
| `MDAGENT_KB` / `MDAGENT_UKB_ROOT` | 证据系统适配层开关与根；生产由 `run-dsh.*` 固定 |
| `data/ukb/system_auto.token` | 机器观察自动入库的 `mdagent-system` token；权限应 0600（Windows 上 chmod 不生效，需 ACL） |

首个管理员由 `ukb_store.init()` 或 `tools/kb/bootstrap.py` 创建；`ensure_admin_token()` 用于轮换/恢复，轮换会使旧 token 失效。
