## 部署方式

- 用 CLI 依次执行 `init`、`setting`（intake/checkout 根目录、每日上限 40）、`load-pack data/domain/metal_md`。
- `python -m ukb serve` 作为独立进程运行；管理员只通过 HTTP 操作，包括登录、在队列页一键批准、在任务页做决定。
- 4 个写入 Agent（MCP 子进程）并发投递，1 个预审 Agent（checker）负责预审，1 个读取 Agent（reader）模拟下游使用。
- 预审逻辑由脚本里的确定性检查器代替：它读完全部材料页，检查重复标题、标签是否在标签树中、是否只挂了父标签、文档定位能否解析。这部分**没有测真实 LLM 的预审质量**。

## 结果（65 项检查，全部通过）

- **投递**：57 条全部通过"先查范围、再投递"的流程进入审核，4 个 Agent 并发投递用时 2.9 秒。
- **6 类边界投递都按预期处理**：带轨迹文件被拒（FILE_TYPE_DENIED）、缺来源说明被拒（ORIGIN_REQUIRED）、读取投递目录以外的文件被拒（FILE_SOURCE_DENIED）、未知标签被拒（TAG_UNKNOWN）、失效定位被拒（LOCATOR_INVALID）、正文含凭证被隔离后驳回。新标签与已有别名冲突时被拒（TAG_EXISTS）。
- **预审**：59 个任务用时 8.7 秒，投递方看不到自己的任务。预审识别出一条近重复，管理员把它并入已有条目。另有 14 条预审给出"只挂了父标签，可考虑子标签"的建议，这些条目留给清理时决定是否改标签。
- **管理员**：在 HTTP 队列里一键批准 57 条；新标签"冲击加载"经审核转为正式标签；一条修订批准后成为当前版本；一条负面反馈触发复审，结论为保持。
- **下游读取**：13 个问题按标签或别名路由，全部命中预期内容，每次读取 1 到 17.5 千字。例如"pair_coeff 报错"走"元素映射"别名，"铜的弹性常数"走"弹性常数 × 铜"，"冲击"走新建的标签。
- **文档型条目**：
  - 145 KB 的日志可以分页完整读完；
  - 案例定位 `in.npt:L38` 正好落在 npt fix 行；
  - checkout 出来的文件与基准原件 sha256 一致，再次 checkout 时拒绝覆盖；
  - 报告可以按章节读取；
  - 中文 PDF 第 2 页能读到"层错能"。
- **限流**：每日上限在第 25 条探针投递时触发，这 25 条探针已被驳回。
- **运维**：lint 没有严重问题，审计链完整，导出和备份都成功。库文件 1.11 MB，附件 0.53 MB。
