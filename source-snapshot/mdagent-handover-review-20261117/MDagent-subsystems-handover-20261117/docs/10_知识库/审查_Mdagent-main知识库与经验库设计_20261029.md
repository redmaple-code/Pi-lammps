# MDagent main 知识库与经验库设计审查

日期：2026-10-29。任务 T-031；证据 EV-20261029-002。

## 结论与范围

总体判断：main 的知识与经验设计在数据建模上有清楚的分层和派生关系，但“观察记忆 → 人工审定晋升 → 经验包供多个消费者检索/使用”的统一闭环没有在该基线上接通。atoms 记忆、SOP/知识卡和 review_experience 包并非简单重复：前者记录观察事实，后者承载可复用的约束与经验，知识卡是派生浏览视图。问题在于二者之间缺少已实现的单一晋升写入路径、普适本地检索入口，以及一致的来源/状态校验；因此设计稿承诺的“单一事实源、单一晋升通道、多服务面”尚未实现为可验证的端到端契约。

审查基线为本机缓存的 `origin/main@c40deb2cb96fcd2cb8e0c05621371d0203505648`，不是当前工作分支，也不是过期的本地 `main@4c547aa`。T-030 已记录本地 main 落后该缓存 34 个提交、远端查询失败；本审查没有重新取得 GitHub 最新状态，故不能断言该缓存仍是线上最新 main。检查采用缓存 main 的脱敏代码树与已归档设计材料；运行时知识数据已从脱敏导出中移除，故不评价服务器上的真实 atoms、SOP、知识卡及运行时经验内容，也不把数据包存在等同于运行时已接线。

这是只读设计与源码审查。未修改产品源码、未运行测试、真实仿真、LLM 或服务器服务；以下结论不是产品验收，也不是生产环境测试结果。

## 架构核对

| 层/资产 | 设计角色 | main 中可见实现 | 评价 |
|---|---|---|---|
| L0 / 既有事件与 LEDGER | 保存原始事件和演化审计依据 | `memory.py` 读取 LEDGER；提案应用记录 LEDGER | 有来源材料，但本审查未检查脱敏库之外的运行时日志 |
| L1 atoms | 原子化记录观察事实并带 refs | `record_atom()` 限长、去重、限制 refs 数量并在支持的平台上加文件锁；尝试打轴标签 | 事实层清晰；锁在无 `fcntl` 平台退化为无锁，部署风险需结合目标平台评估 |
| L2 scenarios / L3 SOP | 从 atoms、LEDGER 重建聚类与规则视图 | `rebuild()` 全量确定性重建 scenarios/SOP，并排除已回滚修复作为有效修复 | 派生关系及可回溯设计较好；仍须运行时数据与重建测试证明具体账本正确 |
| knowledge cards | 面向人类浏览的派生卡片，不作第二事实源 | `build()` 从 atoms、SOP、notes 构建并整体替换；人工 review 状态单独保存。可选 LLM 被提示只归纳给定事实，LLM 不写人工核卡状态 | 事实骨架确定性、人工核验与蒸馏分离；提示词约束不是事实正确性的形式证明 |
| tagging / replay | 受控分类、引用检查、历史回放质检 | topic 与候选 topic 分轴，method/ops 由数据词表标注；`verify_refs()` 可核文件引用；`replay_eval.py` 对历史事件与考题引用做后验校验 | 防止自由文本直接等同认证经验的设计有效，但 refs 文件存在性不代表来源内容真实或仍适用 |
| review_experience | 经治理、按状态供评估/门禁等消费者使用的经验条目 | 有版本化种子包与运行时目录；数据格式声明 provenance、status、refs；证据侧消费者可载入多类条目 | 经验包与 atoms 是不同生命周期的数据模型；缺少和 atoms 晋升闭环及统一的加载信任契约 |

## 发现

### 高：经验晋升链路在 main 中未闭合

设计文档 v1.0-r3 §5.7 明确将晋升描述为 observe → proposal → 人工闸 → review_experience，且同一经验应多消费方共享。缓存 main 的 `apply_proposal.py` 成功应用后经 `record_atom()` 写入演化变更 atom 并触发 SOP 重建；没有写入 review_experience 的调用。`mcp/review_experience/README.md` §“与演化层的对接”仍将该集成标作预留，机器注入待演化通道接入。由此，观察事实层和供评估使用的经验规则层虽有 refs/provenance 字段设计，实际晋升、人工核准、状态转换和回链并未形成一个可追溯的端到端流程。人工直接落文件也绕过了 apply_proposal 的提案与 LEDGER 路径。

### 高：设计审阅经验缺少其预期消费者

review_experience README 将设计审阅 AI 的 `design_review.run()` 描述为经验包消费者；缓存 main 中没有 `mcp/design_review.py`、`physics_gate.py`、`md_proj_mcp.py` 或 `webui/`。证据侧仍有 `assessment.py`、`deep_review.py`、`stage_gate.py` 等经验数据消费者，但它们不等于设计审阅流水线。因而该 main 基线中的设计审阅类经验数据不能按 README 所述注入 AI 设计审阅；包已存在不代表设计审阅能力已经进入此 main。

### 高：经验包来源与状态校验不统一

`stage_gate.exp_status_index()` 扫描种子目录、`REVIEW_EXPERIENCE_DIR` 和数据根运行时目录；缺失 `status` 默认为 `active`，坏 JSON 被跳过，未检查 provenance 或包签名。`load_methodology_entries()` 仅排除 `revoked`，其他未知状态仍可能进入 E4。`evidence_grade.resolve()` 对经验条目同样主要排除 `revoked`，并将 `canary` 降为 soft-only；不同消费者对允许状态并不统一。当前实现因此把可写运行时目录的文件视作知识输入，且缺字段可获得 active 效力。README 中的 provenance 字段是数据格式声明，不是代码级真实性或授权验证。

### 高：E4 无方法论条目时静默跳过

`stage_gate._e4()` 在 `load_methodology_entries()` 返回空列表时仅写入“知识包为空”trace 后直接返回，不添加拒因。经验包缺失、不可解析、无方法条目、全部被撤销与“该阶段经明确治理决定不适用”在这一分支上无法区分；若 E4 是阶段必需检查，这就是 fail-open 路径。应先由策略明确哪些阶段/域允许显式空集，再以必需包清单或等价的显式 N/A 记录区分配置缺损与有意不适用，不能依赖隐式空列表表示通过。

### 中：atoms / SOP / 知识卡缺少 MCP 本地检索面

缓存 main 的 MCP 注册表提供 `sim_search_sessions`，检索对象是历史会话存档，不是 atoms、SOP 或知识卡；本地外部语料检索器也是 CLI。证据门可校验任务提供的 `atom:<id>` / `exp:<id>` 引用，但这不是按当前问题检索并返回本地经验的服务面。结果是这套记忆更多依赖调用者已知 ID 或其他外围路径，未体现设计稿所述面向 AI/用户的检索消费能力。

### 中：RSI 图谱缺失时引用检索静默降级为空

`observe.py` 指向 `evolution/rsi_knowledge/graph.json`，但该文件不在缓存 main 树中。`rsi_references()` 捕获加载异常后把节点设为空列表，后续检索会返回空引用而不向提案或操作者暴露资产缺失。它不破坏 atoms 主账本，但会让设计宣称的 RSI 参考检索在该基线上无声失效。

### 边界：脱敏源码不能证明运行时知识账本质量

`SANITIZATION.md` 说明运行时 atoms、scenarios、SOP 和蒸馏数据不随脱敏源码导出。当前仓库可核查结构和消费代码，不能核验服务器上的原子质量、重复/过时比例、引用存活率、知识卡生成结果、运行时包来源或实际检索命中率。外部语料行数也不能作为内部经验完整性的证据。

## 建议的设计闭合顺序

1. 先冻结知识对象与生命周期契约：区分原始观察 atom、可执行/可引用经验条目、派生场景/SOP/卡片；规定唯一晋升入口、人工审批证据、atom↔experience 回链、canary/active/revoked 状态转换及撤销传播。避免把经验包简单复制成另一份事实库。
2. 为所有消费者统一加载验证：必需的包身份/版本/来源/审批元数据；拒绝缺失或未知状态；检测重复 ID 和覆盖顺序；明确运行时目录的信任边界。跨消费者共享同一解析与状态策略。
3. 明确各阶段经验包的必需性和可空条件；缺包/损坏/意外空集要区别于经审批的显式 N/A，并让 E4 的结果可审计，符合选定的 fail-closed 语义。
4. 决定此 main 的产品边界：若设计审阅在范围内，应将经验包实际接入其消费者并核对缓存 main 中代码是否已进入；若不在范围内，应更新 README/设计文档，避免把别的分支或未合并能力说成 main 已提供。
5. 明确本地知识检索接口与排序/来源展示；若有意只支持 ID 引用，应将该限制写入架构与工具契约，而不要将会话搜索或外部 CLI 当作等价能力。
6. 恢复 RSI 图谱资产，或由调用方显式报告不可用；补充无图谱、空经验包、状态异常、重复 ID、来源伪造、晋升撤销传播及端到端检索测试。
