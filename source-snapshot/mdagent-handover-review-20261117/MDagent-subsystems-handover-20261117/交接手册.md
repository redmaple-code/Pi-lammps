## 1. 系统边界

本包抽出四个可独立部署的系统，以及它们共享的底座：

1. **知识库 UKB**：`src/ukb/` + `src/evolution/kb/` + `src/tools/kb/`。
2. **证据系统 v3**：`src/evolution/evidence_v3/` + `src/mcp/evidence_*.py` + `src/webui/`。
3. **门禁系统**：前置双门 `src/mcp/{md_proj_mcp,design_review,physics_gate}.py`、阶段门 `src/evolution/{stage_gate,stage_state,surface,assessment,content_check,config_check,deep_review,evidence_grade}.py`、Agent 侧插件 `src/dsh-plugins/dsh-md-{flow,ops}-gate`。
4. **物理一致性校核**：`src/design-review-layer/`（`review_layer/`、`web/`、`cases/`、`reports/discovery/`）。

共享底座：`src/mcp/review_experience/`（经验包）、`src/mcp/paths.py`（数据根）、`src/mcp/md_mcp.py`（工具面）。

**不在包内**：`cloud/gate.py`（Web 租户访问闸）、`bio-agent` 平台门、求解器与 HPC 运行时、`MDagent-src` 的五段主工作流。它们与这四套系统通过数据工件解耦，需要时从原仓取。

## 2. 通用运行模型

### 2.1 数据根

所有运行期状态在 `<数据根>` 下，路径解析唯一出处是 `src/mcp/paths.py`：

1. 环境变量 `MDSIM_DATA_ROOT`
2. `src/mcp/md_config.json` 的 `data_root`
3. 默认 `<代码根父目录>/mdsim-data`（包内即 `<包根>/mdsim-data`）

UKB 存储在 `<数据根>/ukb`（`MDAGENT_UKB_ROOT` 可覆盖）。测试通过临时数据根隔离，互不污染。

### 2.2 知识开关

`MDAGENT_KB=ukb|legacy`；未设置时依次读 `<数据根>/kb_mode.json`、`src/mcp/kb_config.json`。**未知值 fail-closed**。包内 `kb_config.json` 只声明 `ukb_root: "data/ukb"`，不强制模式。

### 2.3 经验包

`src/mcp/review_experience/*.json` 是数据文件，不是代码：

- 包级 `consumer` 字段区分消费方：`evidence` 的包（`anchors_seed`、`methodology_deep`、`confirmation_surface`）由证据门消费，双门审阅整包跳过；无 `consumer` 或 `design-review` 的包由双门审阅消费。
- 运行时目录 `<数据根>/memory/review_experience/` 可覆盖/热加载（mtime+size 缓存），坏包隔离。
- 新经验以 `status: "canary"` 降落，只能支撑 soft 结论，经回放证据晋升。

## 3. 知识库 UKB

### 3.1 代码地图

| 路径 | 职责 |
|---|---|
| `src/ukb/ukb/core/schema.sql` | 表结构（entry / revision / blob / review / audit / registry …） |
| `src/ukb/ukb/core/{registry,typespec}.py` | 12 类注册表（类型/分类面/标签/条件键/关系/来源类型/口径/高危规则/文件格式与角色/设置…） |
| `src/ukb/ukb/core/{intake,documents,contribute}.py` | 投递、文档型条目（摘要层+原文层）、文件复用 |
| `src/ukb/ukb/core/{review,navigate}.py` | 预审/管理员审核、分级检索（overview→catalog→read） |
| `src/ukb/ukb/api.py` | 统一入口，每个写操作一个事务 |
| `src/ukb/ukb/mcp_server.py` | Agent 工具面（16 工具，**不含**管理员决定） |
| `src/ukb/ukb/webui.py` | 管理员审核台 |
| `src/ukb/ukb/cli.py` | 命令行 |
| `src/evolution/kb/adapter.py` | MDagent 旧知识入口兼容层，保持原签名/返回形状，`raw_json` 保真 |
| `src/evolution/kb/client.py` | 统一 `KnowledgeBase` 接口（读/写/审核/状态/标签/注册表/文档/备份/健康/历史） |
| `src/tools/kb/` | bootstrap / import_legacy / verify_import / compare_modes / prereview / review_queue / serve / ensure_evidence … |

### 3.2 写路与审核

```
propose（人或 AI，AI 必须带 origin）
   → AI 预审（另一 Agent，投递方不能预审自己；只作参考）
   → 管理员批准（哈希绑定内容；MCP 通道不接受管理员决定）
   → 可检索
```

- 每次状态变更绑定内容哈希与 `expected_revision`，防止并发覆盖。
- 注册表扩展也走 `propose-registry → 批准`，不改表结构。
- 文档型条目：摘要层可直接读；原文按章节/页/行读；文件复用走 checkout 并附 provenance。
- 不入库文件：轨迹、检查点、压缩包、可执行文件、密钥等，见 `src/ukb/data/seed/file_deny.json`；未登记格式拒绝。

### 3.3 与证据/校核的耦合

- `evolution/kb/adapter.py::knowledge_snapshot` 把已批准条目绑定为任务知识快照；UKB 变更后 `evaluate` 返回 `REVALIDATION_REQUIRED`，必须 `refresh_knowledge` 再审查。
- `design-review-layer/review_layer/ukb_store.py` 读取三类条目：基线维度（rule，9）、常见问题（lesson，12）、审查点（observation，24/25）。
- 证据记录可发布为 `evidence_claim` 候选，必须经 UKB 审核才成为知识。

### 3.4 初始化与维护

```bash
cd src
python tools/kb/bootstrap.py --admin <ID> --data-root <数据根>
# 或
cd src/design-review-layer && python -m review_layer.ukb_cli init --admin <ID> && python -m review_layer.ukb_cli seed-all
```

- 令牌只在创建时显示一次；`system_auto.token` 供机器观察路径，权限应收紧。
- 备份/恢复：`ukb.core.maintenance`；导入旧库用 `tools/kb/import_legacy.py`，核对用 `verify_import.py`。
- 冻结校验：`cd src/ukb && python tools/freeze.py --check`（`RELEASE.json` 记录 79 个文件 sha256）。

## 4. 证据系统 v3

### 4.1 代码地图

| 路径 | 职责 |
|---|---|
| `src/evolution/evidence_v3/service.py` | 任务服务：状态、计划、审查、评估、推进、授权、完成 |
| `src/evolution/evidence_v3/policy.py` | 策略校验：阶段凭据、授权边界、证据分级、冲突裁决 |
| `src/evolution/evidence_v3/planning.py` | 计划/义务/阶段推进 |
| `src/evolution/evidence_v3/knowledge.py` | 知识快照、发布/重验、代数（generation）控制 |
| `src/evolution/evidence_v3/measurements.py` | 测量记录与结果绑定 |
| `src/evolution/evidence_v3/{store,retrieval,execution,contracts,migration}.py` | 工件存储/原子写、检索、执行桥契约、canonical hash、迁移 |
| `src/mcp/evidence_api.py` | 28 个 action 的 dispatch（`sim_evidence` 的实现） |
| `src/mcp/evidence_review.py` | 审查流水线：分批、预算、引用核验、全局关系、结论 |
| `src/mcp/evidence_{discovery,execution,bridge,worker}.py` | 发现/执行/进程桥/后台 worker |
| `src/mcp/human_authority.py` | 带外人工授权：park → 所有者决定 → attestation |
| `src/webui/server.py` | 本地 Web UI：默认只转发 12 个公共 action，执行需显式 `--enable-execution` |

### 4.2 工作流

```
recognize → retrieve → propose/discover → init → plan
   → evidence/measure → review → evaluate → advance → complete
另有：authorize（单次动作许可）→ finish；reconcile_start（启动对账）
```

- **证据与授权分离**：`authorize` 只签发当前输入、当前阶段、单次动作的许可；证据记录不能当许可用。
- **状态机**：每次变更需 `expected_revision`（可选 `expected_state_seq`）；`request_id` 幂等重放；任务级 + 代次级文件锁；整写 `tmp + os.replace`；备份 `O_EXCL`。
- **不可变工件**：证据/测量/审查/授权/运行工件写入后校验哈希，篡改报 `ARTIFACT_MISMATCH`。
- **知识重验**：任务创建时绑定 `knowledge_snapshot`；UKB 变更后 `evaluate` 返回 BLOCK（`REVALIDATION_REQUIRED`）。
- **执行桥**：进程树超时终止、清理宽限期、审计 JSON 不完整不算成功、超时不产生完成回执。

### 4.3 数据工件

```
<数据根>/memory/tasks/<task_id>/
  state.json                 唯一状态（含 revision / generation / knowledge_snapshot）
  decisions/                 decision 工件（不可变）
  evidence/ measurements/ reviews/ authorizations/ runs/ receipts/
  gate-log.jsonl review-log.jsonl open-issues.md work-log.md
<数据根>/events/{toolcalls,pipeline}.jsonl   审计账
```

### 4.4 入口

- MCP：`sim_evidence(action=…)`，28 个 action 与 `evidence_api.dispatch` 一一对应；`sim_exec` 只接受 `task_id/permit_id/request_id/spec`。
- Web：`python -m webui.server --data-root <数据根> [--enable-execution]`。
- 测试：`src/tests/test_evidence_v3_*.py`（218 项）。

### 4.5 部署前提

- 真实执行需要 `md_config.json` 的 `evidence_execution_registrations` 和 kit 审计桥（`agents/runtime/v3.3/claude_interface.py`）；缺失时 `sim_selfcheck` 报告缺口，`sim_exec` fail-closed。
- 真实审阅需要 `model_research` 的供应商凭证（Kimi / BigModel / 本机中转站，按顺序回落）。

## 5. 门禁系统

门禁分三层，互相独立但共享数据：

### 5.1 前置双门（方案质量）

```
DRAFT ──(open_questions 全答)──▶ CLARIFIED
CLARIFIED ──(design 四要素 + C2e 证据/假设)──▶ DESIGNED
DESIGNED ──confirm_intent(用户批准原话)──▶ CONFIRMED
CONFIRMED ──validate_intent──▶ GATED_PASS | GATED_FAIL
GATED_FAIL ──update_intent(minor_revision)──▶ CONFIRMED
其他改动 ──▶ DESIGNED（revision+1，重走终审）
```

- 入口 `src/mcp/md_proj_mcp.py`：9 个受控写工具、五道写闸、R-VERIFY 责任闭环。
- 审阅 `src/mcp/design_review.py`：FACTS→EXPERIENCE→BRIEF→REVIEW→ARBITRATE；A–I 八层 rubric、三档严重度；审阅不可用或输出不可解析 → 合成 `REVIEW-INFRA` 硬拦。
- 度量 `src/mcp/physics_gate.py`：纯几何/势函数解析（`dmin`、组分、结构指纹、衍生比值、结构存在性扫描、task_grade），**不做判断**。
- 经验：`src/mcp/review_experience/`，消费者标记见 §2.3。
- 设计基线：`docs/30_门禁系统/设计_前置双门功能设计定稿_v1.0.md`；实现规格：`docs/30_门禁系统/设计规格_仿真方案设计与物理一致性校核.md`。

### 5.2 阶段机械门（证据门）

- `src/evolution/stage_state.py`：任务状态机读写（per-task 锁、原子写、决策工件 `O_EXCL`）。
- `src/evolution/stage_gate.py`：E1–E5 五条实质规则 + 阶段绑定 + fail-closed；核验 `surface`（核查面）覆盖。
- `src/evolution/surface.py`：动态核查面（旧 `project_checks` 的替代），条目来自 `confirmation_surface.json`。
- `src/evolution/{assessment,deep_review,content_check,config_check,evidence_grade}.py`：快检锚、方法论深审、数值对账、配置组合机检、证据分级。
- 规则数据与经验包分离：规则本身在数据文件，核心代码不含具体域字面量。

### 5.3 Agent 侧布防

- `src/dsh-plugins/dsh-md-flow-gate/lib/index.js`：按对话意图在工具选择阶段布防（状态/力场/证据工具），记录违规到 `<数据根>/events/flowgate.jsonl`。
- `src/dsh-plugins/dsh-md-ops-gate/lib/index.js`：高危运维操作闸。
- 测试：`node src/tests/test_flow_gate.mjs`（27 项）。

### 5.4 执行写门

`sim_exec` 是唯一写门：只消费服务端核验的 `task_id + permit_id + request_id + spec`，经 kit `claude_interface` 审计通道执行；`validation` 与 `production` 分离；`START_UNKNOWN` 不得重发，必须 `reconcile`。

## 6. 物理一致性校核

### 6.1 代码地图

| 路径 | 职责 |
|---|---|
| `src/design-review-layer/review_layer/consistency.py` | 一致性引擎：intent 字段 ↔ in 文件实现，9–10 项检查，五档判定 |
| `src/design-review-layer/review_layer/review.py` | 零规则审核层：只做确定性汇总，`findings` 恒为空 |
| `src/design-review-layer/review_layer/{full_report,audit_report,discovery_report,export_bundle}.py` | 报告生成 |
| `src/design-review-layer/review_layer/ukb_store.py` | UKB 读取（基线/常见问题/审查点），`REVIEW_KB=legacy` 回退本地 JSON |
| `src/design-review-layer/review_layer/rules/infile_rules.json` | 命令用途白名单（数据驱动，不是代码规则） |
| `src/design-review-layer/web/design_plan_server.py` | 8900 交互页与 7 个只读 API |
| `src/design-review-layer/cases/case1..5/` | 夹具（intent + in.case），页面内置可跑 |
| `src/design-review-layer/reports/discovery/` | 审查点发现输入数据 |

### 6.2 检查项

系综、时间步（支持 `variable` 链）、步数、units、pair_style、势函数文件、温度、加载速率（ps⁻¹→s⁻¹，20% 容差）、观测量、命令用途。

### 6.3 五档判定与汇总

| 判定 | 含义 |
|---|---|
| `ok` | 目标/声明与实现一致 |
| `questionable` | 需补充说明或证据 |
| `unproven` | 无法核对 |
| `invalid` | 实现与目标直接冲突 |
| `plan_conflict` | 方案字段过期/自相矛盾（**修订方案，不是否定仿真**） |

汇总（仅确定性映射）：任一 `invalid` → `FAIL`；否则任一 `plan_conflict` → `NEEDS_REVISION`；否则任一 `questionable/unproven` → `REVIEW`；全 `ok` → `PASS`。

### 6.4 运行

```bash
# CLI：真实 MDagent 工件（只读）
cd src/design-review-layer
python -m review_layer.cli --case <case_id> --mdagent-root <MDagent 工件根> --out reports

# CLI：夹具
python -m review_layer.cli --intent cases/case1/intent.json --infile cases/case1/in.case --fixture

# 交互页（内置 case1–5）
cd web && python design_plan_server.py 8900

# UKB 播种与查询
python -m review_layer.ukb_cli seed-all
python -m review_layer.ukb_cli stats|baseline|common
```

- 模板 `web/static/design-plan.html` 为 v1.3 冻结，`python -m review_layer.template_check` 校验 sha256。
- 设计校核的知识/经验/证据读取已接入 UKB；`sources.py` 的通用适配器仍是 Null 占位。

## 7. 部署与集成

### 7.1 Windows（本包验证环境）

- Python 3.11.4 + Node 22.19.0；`numpy` 仅 `physics_gate` 需要。
- 无 `fcntl`：`stage_state` 自动用 `msvcrt` 兜底；令牌文件 `chmod 0600` 不生效，需 ACL。
- 路径尽量短：证据审阅的默认预算按字节计，知识快照里含绝对路径；安装目录过深可能触发分批路径（功能正确，但测试里的单批 mock 不适用，见 `PACKAGING-NOTES.md`）。

### 7.2 Linux 服务器

- 恢复 `md_config.json` 的 `exec_bridge.sudo_user`（如 `mdorch`）；Windows 本机为空的配置不要带到服务器。
- kit 审计桥位于 `agents/runtime/v3.3/claude_interface.py`，通过 `MDSIM_KIT_BASE` 注入。
- 令牌与数据库放在受控目录，服务账号只读/读写权限分离。

### 7.3 MCP 挂载示例

```jsonc
{
  "mcpServers": {
    "mdsim":  {"command": "python", "args": ["<包>/src/mcp/md_mcp.py"]},
    "mdproj": {"command": "python", "args": ["<包>/src/mcp/md_proj_mcp.py"],
               "env": {"MDPROJ_ROOT": "<项目根>", "MDSIM_DATA_ROOT": "<数据根>"}},
    "ukb":    {"command": "python", "args": ["-m", "ukb.mcp_server", "--root", "<数据根>/ukb",
                                              "--agent", "writer"], "cwd": "<包>/src/ukb"}
  }
}
```

## 8. 已知问题与风险

### 8.1 上游遗留（未在包内修改）

- **H1 `_find_run_dir` 前缀匹配**（双门）：`case_id=foo` 会命中 `foo_bar`。修法见 `docs/30_门禁系统/审计_双门功能事实核查与漏洞清单_20261018.md`。
- **H2 审阅简报硬截断**：长方案的四段与 `key_params` 可能被截到 6000 字符外。
- **证据桥超时用例对负载敏感**：高负载下可能报 `bridge-termination-unknown`，空载 9/9。
- **Windows 权限**：令牌文件权限位无效。
- **真实模型/求解器未在本包验证**：缺凭证与执行适配，相关 action 明确 fail-closed。
- **`cloud/gate.py`、`bio-agent` 平台门未打包**：与本四系统解耦。

### 8.2 打包时修复/适配（详见 `PACKAGING-NOTES.md`）

- 恢复 `model_research` 的 `design` 模式（v3 分支丢失，但 `sim_design_research` 仍在调用）。
- 双门种子完整性测试补上 `confirmation_surface.json`（证据消费包）。
- 证据生命周期测试显式给 200KB 审阅预算，消除安装路径长度敏感性。
- 一致性校核生产库断言从 `>100` 改为 `>=45`（新播种库的合法规模）。
- flow-gate 的 `~` 展开改用 `path.resolve`，修 Windows 混合分隔符。
