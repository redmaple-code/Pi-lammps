## 2. 具体实现与验收场景

### HR-W01：可复现基线

改动点：原 `tools/run_verification.py`、README/交接手册、初始化入口和依赖说明。新增独立测试工作目录与外置输出参数，不修改原 verification。启动时记录 ZIP/源码摘要和去敏配置；超时、缺命令、初始化失败都写完整最终回执。

- HR-ACC-01：全新环境按一条命令路线完成初始化与播种；重复初始化清楚报告“已存在”，不轮换任何既有管理员 token；每个服务解析同一库身份。
- HR-ACC-02：预置外部 REVIEW/MDAGENT 根及已有 admin 文件，运行测试前后摘要不变；正常、超时、播种异常均只清理本次创建的临时资产。凭据不得进入日志/交付 ZIP。
- HR-ACC-03：套件发现数为零、计数解析失败或必要套件缺失时验证失败；passed/failed/error/skipped 分开统计；手工历史冒烟不变成本次自动通过；重复复测不覆盖原证据。JSON/Markdown 从同一结果生成；原生 Windows locale、仅 stdio UTF-8、完整 UTF-8 模式均验证协议编码，不因中文错误消息导致读取线程崩溃。

### HR-W02：身份与持久化

改动点：`md_proj_mcp._find_run_dir/_load_intent/_save_intent/_audit` 及写入口。原包中先落文件事务；Pi 侧由 K6 接管同一行为。

- HR-ACC-04：同时存在 foo、foo_bar、foo 的多个 run；查询指定 run 精确命中，不完整/多义请求拒绝；工件内部身份不符、目录越界和链接逃逸均不得写入。
- HR-ACC-05：分别在临时文件写入、replace 前后、审计投影前后注入中断；旧/新权威 JSON 总有一个完整版本；重启能从操作记录确定结果，无无凭据成功，也不重复推进。
- HR-ACC-06：两客户端读取同版本并更新；只允许一项提交，另一项冲突并保留原候选；同 commandId 同内容回同回执，异内容冲突；重复调用不增加版本/审计事件数。

### HR-W03：审阅完整性

改动点：`design_review.build_brief`、模型 transport/回执；复用 v3 的预算机制前先核对协议与身份规则，不能只增加 6000 上限。

- HR-ACC-07：关键条件分别放在第 6001 字符后、第三个输入文件、文件第 3001 字符后；审阅实际收到对应范围且回执可核，或明确 incomplete；不得出可消费通过。
- HR-ACC-08：分块缺一片、预算耗尽、模型无凭据、响应不可解析、方案在审阅期间变化，均不能以已有部分结果放行；完整同摘要输入可正常通过确定性契约校验。

### HR-W04：一致性覆盖

改动点：`review_layer.review.summarize`、models、检查集声明和 UI 报告。

- HR-ACC-09：空列表、未知 verdict、重复 checkId、必需 check 缺失被拒绝/REVIEW；完整全 ok 为 PASS，invalid/plan_conflict/questionable/unproven 保持原有优先级。
- HR-ACC-10：无法解析的变量链/include/未知语法显式 unproven 或 unsupported；报告可见缺口；fixture PASS 不成为科学验收。对五个既有 fixture 做前后差异核对，解释所有改变。

### HR-W05：人工决定

改动点：confirm_intent、可信宿主入口和 human_authority 的可复用验证部分；不得让模型同时持有签发决定的密钥。

- HR-ACC-11：只提供 confirm_quote、伪造 actor/source、旧摘要决定、跨案决定、撤销/过期决定均不能进入可信 CONFIRMED；真实决定引用绑定当前方案后成功，原话仅作为附件保存。
- HR-ACC-12：导入历史 CONFIRMED 保留原事实，但不能签发新执行许可；方案批准不代替 production 授权；同决定是否可复用必须按其明确作用域验证。

### HR-W06：统一契约与 Pi 集成

产物：逐 action 的输入/输出/错误/读写/版本/幂等/授权表，来源 capability 矩阵，旧状态迁移与单写路由，生产者/消费者 fixtures。补充 docs/module-development 对应任务的实现回执时才改变实现状态。

- HR-ACC-13：冲突数据根启动失败并列出非敏感配置来源；缺 kit/凭据/注册表时受影响能力 unavailable，独立只读能力可用；不跨库悄悄降级。
- HR-ACC-14：旧 schema 只读；v3→Pi dry-run 数量、引用及摘要闭合；切换后旧写入口拒绝；重复导入不多建对象；revision/state_seq/generation 不混成同一字段。
- HR-ACC-15：贯穿“当前输入→审阅→决定→许可→运行回执”，改输入或撤回授权使旧许可失效；模拟发送后超时，持久 unknown 并对账，外部启动计数不超过一；不得用 mock 结果关闭真实环境验收。

### HR-W07：知识与恢复

改动点：knowledge 适配、common_issues/discovery 的 mode 行为、备份清单与恢复入口；保护现有 UKB 审核链。

- HR-ACC-16：生产 UKB 不可用时相应 gate 阻塞；显式 fixture 可显示降级报告；Null source 与真实空结果不同；固定 entry@revision 回读与来源摘要匹配；candidate/trial 不自动升级。
- HR-ACC-17：备份含带原文附件的条目，在空目录恢复后 DB、blob、旧修订、查询、原文与审核链一致；删一个 blob/改摘要应拒绝切换；凭据按独立路径恢复，旧服务可继续运行。
- HR-ACC-18：导入新旧状态和重复批次、冲突 ID/内容；保留 rawStatus、来源与历史审核文本；缺历史证据保持未验证，不能因导入成功而确认知识或科学结论。

### HR-W08：完整交付

产物：冻结源码/集成提交、patch 账、依赖与许可证清单、目标环境配置样例（无 secret）、可重跑 MCP/Web 冒烟与现场恢复记录。

- HR-ACC-19：按清单从冻结快照重建产物字节；修改后来源仍可追踪；依赖安装在无原工作区前提下完成；实际分发与引用第三方分别列明，保留许可。
- HR-ACC-20：Windows 与目标 Linux 分别执行锁/符号链接/权限/进程终止；MCP initialize、tools/list、一个只读调用及一个受控拒绝；Web 首页、健康、API、无权限变更拒绝，记录真实返回。
- HR-ACC-21：受控真实模型与 validation 求解任务验证输入摘要、计量单位、许可、进程/调度器 ID、退出、输出哈希和对账；production 单独验证授权及边界。科学人员依据已锁指标验收，不以进程退出码替代科学通过。

## 3. 关闭与发布门槛

代码任务关闭需：准确实现 diff/commit、上述验收的输入/命令/原始日志/结果、正常及失败回执、文档同步、已知限制。任务因环境缺失不能实测时保持 notVerified；可以完成机制部分但不能将整个验收项置 passed。

可先发布只读演示或修复候选包，显式能力边界。支持正式方案确认前关闭 HR-03/04/05/06/07；生产知识切换前关闭 HR-01/02/09/10；Pi 写入接管前完成 HR-W06；完整生产交接仍需 W08。源码修复、文档审阅和用户产品接受分别记账。
