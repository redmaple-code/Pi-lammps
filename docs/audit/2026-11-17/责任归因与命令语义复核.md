## 再核查得到的命令语义错误

### AI-041 — fix print 的变量语义被检查器误解

检查器 MB-005 看到 `${...}` 就判失败。LAMMPS 的 fix print 支持在双引号字符串内对变量逐次求值。

本次实际运行下列命令，输出正确的 0–10 步及对应的 0–0.01 ps 时间。检查器却返回 failed。

```lammps
variable current_step equal step
variable current_time equal time
fix sampled all print 1 "${current_step} ${current_time}" file variable-print.csv screen no
```

这是开发 AI 把合法命令含义写错进规则的确定反例。此前“避免裸 v_name”的局部检查被错误扩大为拒绝 `${...}`。

### AI-042 — 把应变中的当前长度误当成未冻结参考长度

MB-001 拒绝 strain 表达式中出现 lx/ly/lz。正确的工程应变本来就需要当前长度与冻结初始长度共同参与计算。

```lammps
variable saved_length equal $(lx)
variable L0 equal ${saved_length}
variable strain equal "(lx-v_L0)/v_L0"
```

本次真实 LAMMPS 小测试得到 L0 始终为 7.12 Å，末态 lx 为 7.120712 Å，应变为 0.0001。检查器仍返回 failed。它把“参考长度必须冻结”实现成了“应变公式不能读取当前盒长”。

两项反例均为 exitCode=0，检查器误判已保存。[实际命令与结果](../../../simulation/audits/2026-11-17-followup/command-semantics-result.json)

### AI-043 — 本次提供方接入时遗漏原生模型 cost 元数据

首次 HTTP 接入测试已发送正确的 dsv4.1f 请求，但处理响应时 Pi 的 calculateCost 读取 cost.tiers 报错。原因是我新增的提供方注册代码漏填了 SDK 要求的 cost 对象。已补充未配置费率时的零值占位，并保留实际账单未知的说明。后续三个提供方专项测试全部通过。该错误属于本次开发 AI 的接入代码错误。

### AI-001 — EAM 质量覆盖含义漏检

输入先 read_data，再 pair_coeff 加载 setfl。势文件提供的质量成为实际运行值，Cu 采用 63.0，报告仍写 63.55。这也是具体命令/接口含义核对不足。原 MB-006 只检查质量为正及元素顺序，未把实际质量与报告对账。

## aispot-ds 接入状态

默认配置已切换为 aispot-ds 的 dsv4.1f，增加 providerConnection、原生 HTTP 兼容注册和发送前 allowedModels 检查。服务模型目录提供的正式 ID 为 deepseek-v4.1-flash，当前实际请求使用此 ID。交互入口、论文审计入口和角色适配器沿同一模型限制执行。

端点已从 personal-twin L2 台账取得。运行时通过 twin inject 注入的 AISPOT_DS_API_KEY 访问服务，凭据管理遵循 personal-twin 规约。agent-check 可执行一次真实提供方连通检查。

本地 HTTP 测试用例核对请求体模型 ID 和认证头，并检查其他模型在发送前被拒绝。真实 aispot-ds 端点也已返回 SIMULATION_PROVIDER_READY，运行时回执记录 provider=aispot-ds、model=deepseek-v4.1-flash。[真实连通回执](../../../simulation/provider-live-canonical.log)

本轮首次把用户简称 dsv4.1f 直接作为 API 模型 ID 请求，服务返回 model_not_found。查模型目录后使用正式 ID 已成功。这是本轮接入过程中的名称解析错误，归于开发 AI，记为 AI-044。该失败和修正回执分别保存在 provider-live-diagnostic.log 与 provider-live-canonical.log。

### 真实模型工具问答中观察到的问题

模型已真实调用 simulation_source_read 读取题目，并通过 simulation_artifact_publish 发布 JSON。一个关闭思考的问答产物出现了下列问题，编号 AI-046–048。

- **AI-046** 速度主字段 speedMPerS=10，理由又推导出 1,000，并新增 speedMPerS_final=1000。主字段没有同步纠正。
- **AI-047** eamCanSetMasses 主字段为 false，解释承认 EAM 会覆盖先前质量，另一个 questionAnswers 字段又写 true。主字段和解释相互矛盾。
- **AI-048** 对工程应变问题，模型把题目声明的独立片段当成整份顺序输入，借 read_data 出现位置判 false。解释中认可公式本身，在题目的独立片段前提下，主裁决仍不符。

这些是该次真实模型输出的确定问题。该产物属于独立工具问答，主算例的实际速度已从轨迹核对为 1,000 m/s。[原始问答产物及检查](../../../simulation/work/provider-checks/provider-role-check-7f260806-97c4-4c34-929d-56510ab84b70/result.json)

最早一次角色工具检查在 4,096 token 输出上限处结束，未完成发布。接入配置随后补齐 DeepSeek thinking/reasoning_content 兼容参数、推理档继承和更大的输出预算。这项 SDK 适配不足归于本轮开发，记为 AI-045。

默认 low 推理档的真实调用也已完成实读和发布，四个主要答案均正确，保存在 answers 对象中。首次评分器只接受根字段，因而误报全错；题目没有明确要求根字段位置，这属于开发 AI 引入的评分假设，记为 AI-049。评分器已支持明确的答案容器，同时检查多个容器之间的矛盾。重新读取原始 low 产物后，四项主答案通过，原非思考产物的错误和矛盾仍被识别。[low 产物](../../../simulation/work/provider-checks/provider-role-check-ff062a13-ceb8-4080-8422-4c98934bb3f3/result.json) · [复核评分](../../../simulation/work/provider-checks/provider-role-check-ff062a13-ceb8-4080-8422-4c98934bb3f3/assessment.json)

low 产物解释中另有一处确定表述错误，称 step-4000 在第 4,000 步之前把 ramp 置零。该表达式在此前取负值，只有 max(step-4000,0) 这类截断才具有置零含义，记为 AI-050。主算例在第 4,000 步定义 xtip，实际轨迹为 4 ps 内移动 40 Å。

综上，本轮既确认了开发时规则写错，也观察到了真实模型产物中的数值主字段错误、自相矛盾、题目边界误读及解释错误。API 和工具连通证据、模型答案内容与评分器行为均有各自可核记录。
