## 4. 已知缺口与处理

| ID | 已有证据中的缺口 | 影响与下一动作 |
|---|---|---|
| GAP-01 | 原项目缺 raw 案例、手册、纠错语料、势库等目录 | 阻塞 LAMMPS 对应真实验证；补取原资产或显式重建新基线并核来源 |
| GAP-02 | 必需特征、诊断要求等引用文件缺失，MB-008/009 有角色正文依据 | 保留义务，逐项提取正文与实际工具语义后形成可执行规则 |
| GAP-03 | 原证据校验入口存在 stub，旧独立审查与权限机制不足 | 新宿主必须真实验证身份/证据，不能复用退出成功作为通过 |
| GAP-04 | 基座预算/unknown 单测失败，Docker/真实宿主测试跳过 | 实施接入前复核语义；相应环境缺失时保留未验证状态 |
| GAP-05 | 宏观与离散事件领域资产、适配器及真实基准尚未准备 | 本轮只提供 draft 声明；选择并核验具体工具和参考后完成 WP-07 |
| GAP-06 | 旧专项文档、部分旧字段/图形接口存在来源缺口或异文 | 不猜统一；保留两个版本的来源并制定兼容映射 |

这些缺口不阻止规范交付和独立内核开发，但阻止对应功能被标记为已迁移、可发布或科学验证完成。

## 5. 开工顺序与停点

首次源码实施从 WP-01 开始：核对当前版本和工作树，选择隔离分支/工作树，建立真实测试入口，再实现最小契约和负例。当前用户授权止于文档，因此本轮停在规范交付，不启动这些代码动作。

每个工作包收尾维护实现版本和回执；缺口只阻塞依赖它的工作。不因缺少全部科学资产而让契约、状态和解析实现停滞，也不为赶进度降低发布标准。
