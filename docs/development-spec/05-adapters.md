# 05 工具与运行时适配

## 1. 适配器登记

适配器必须声明 adapterId、adapterVersion、contractVersion、capabilities、supportedToolVersions、输入/输出类型、错误映射、取消/续算/对账能力、所需环境配置及验证回执。

适配器只执行其公开能力。领域包引用已注册 ID，不可传入任意模块路径动态加载。新代码扩展需按软件依赖安装、测试和版本化；包内声明不自动授予执行权限。

## 2. 能力调用

能力可以是几何导入、粒子生成、网格生成、模型配置、求解、指标提取、图像生成、知识检索等。能力契约定义输入输出的语义，不只定义文件后缀。

同一个 `field.extract` 也必须区分节点/单元/面关联、参考系、分量、平均方式和单位。转换器必须记录转换方法、版本、损失和验证；不可丢字段后仍宣称同类型。

## 3. 执行生命周期

| 操作 | 必须保证 |
|---|---|
| preflight | 检查依赖、工具/模型支持、输入摘要、当前审查、资源和授权；不声称真实求解 |
| submit | 使用 argv 数组或结构化 API；保存命令/请求、工作目录、身份、输入摘要和外部 ID |
| status | 区分 queued/running/completed/failed/cancelRequested/cancelled/unknown；说明状态来源与观测时间 |
| collect | 关联真实 run 输出，验证要求的文件/数据完整性；成功状态但缺输出也须报缺口 |
| reconcile | 依据稳定身份查询是否发生副作用；不能通过最近文件猜测 |
| cancel | 可选能力；返回已取消或仍待确认，不把发出信号当停止成功 |
| resume | 可选能力；核对检查点、输入模型、工具版本及并行限制，必要时要求新 run |

本地进程需关联 PID 和启动身份，避免 PID 重用。MPI 属于启动方式；Slurm 等调度器属于作业管理；两者不能混为一次“已提交”。队列超时、求解超时、角色等待时限和总预算分别记录。

对话结束不自动取消外部计算；长期工作由持久监督器跟踪。适配器不支持取消时提前声明；用户取消后停止新操作并报告尚在运行的外部工作。

## 4. 执行安全与数据边界

只在已授权工作目录和数据范围操作，路径解析不得越界。参数化调用避免 shell 插值；远程提交脚本也需冻结为工件。日志保留有用的命令与环境信息，但不得记录凭证值。

宿主需在普通工具、Code Mode、MCP 和子委派入口统一检查角色能力与案例目标。活动工具清单不等于硬隔离，可信 Node 扩展也不是操作系统沙箱。

文件覆盖必须通过新工件版本；不得原地覆盖已有运行输入、失败日志或实验原始数据。清理只针对明确归属的临时/孤立内容，并保留可审计范围。

## 5. 运行时与代理

运行时绑定角色职责、模型、推理档位、轮次/成本预算和上下文。厂商模型不支持某档位时给出映射或不支持结果，不能假称完全等价。

角色收到最小充分上下文：方案者读目标/依据，生产者读锁定方案/案例/手册，审查者读产物和规则，分析者读实际 run 和指标定义，协调者读短摘要与状态。完整技术内容进入工件，不靠聊天承担唯一记忆。

独立角色实例必须有独立身份与工具权限；同一模型的两个独立职责会话可形成流程审查，但不能据此声称消除了共同模型偏差。高可信度结论还需程序、实验或独立参考等证据。

## 6. 适配器验收

每个适配器至少验证版本不兼容、坏输入、正常输出、非零/错误退出、缺输出、超时、重复 operationId、提交后中断、取消及未知回执。可选能力不支持时测试明确 unsupported。

mock 证明状态和契约处理；真实工具最小案例证明软件调用和解析；科学基准证明目标模型与方法。三种证据分开记录。工具变更后按其输出和语义影响重跑相关测试，不用全部项目测试掩盖缺少真实集成。
