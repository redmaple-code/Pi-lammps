# 06 知识、证据与改进规范

## 1. 存储与边界

正文/原始材料、条目元数据和搜索索引分离。知识后端可以是文件、FTS、向量检索或外部服务，但必须提供可定位内容、来源、适用条件和真实状态。索引命中不代表确认，排名不代表科学可信度。

条目含 identity/revision、类别、来源、原始位置、originGroupId、领域/模型/尺度/工况/工具适用范围、状态、关系和限制。质量标签与生命周期状态分开。

状态为 candidate/pendingReview/confirmed/quarantined/deprecated/retracted。旧 pending_review 显式映射为 pendingReview；历史 confirmed 若缺裁决证据，保留历史状态并标 legacyUnverified，不能据导入动作认证为新审阅已通过。

## 2. 读路径

任务字段→术语归一→活动包与共享方法范围过滤→检索候选→多样性/同源处理→返回定位和排名理由→实际读取相关内容→核适用条件→绑定决策。

搜索响应至少包含 sourceRef、摘录、定位、status、applicability 和 rankingExplanation。实际读取形成 SourceReadReceipt，记录读取范围、全文/片段/摘要/元数据及限制。没有拿到全文不能称全文已核。

来源相同的多 chunk、多转述或派生报告保留 originGroupId，不能凑独立来源数量。手册解释命令不证明模型对现实适用；实验数据也不自动证明某工具语法正确。

## 3. 证据政策与隔离

通用内核要求证据满足被锁定的政策；各包明确哪些决策需何类来源。LAMMPS 包保留本地实际案例前置、原强制证据分组及相关角色要求；其它领域可使用解析基准、验证算例、实验或制造解，但必须写清用途和验证层次。

默认只检索当前包及声明共享库。跨包资料需显式记录复用理由、模型/尺度/单位差异。用户偏好、聊天记忆和“上次跑过”只提供线索，不替代科学证据。

## 4. 写入与合并

提案→保留原文→分类→提炼最小知识单元→去重/合并建议→适用审阅→发布修订→更新索引。经验采用“情形→问题/风险→修正/检查→来源与限制”。

合并必须读取目标当前版本，给出新增/增强/重复判断、目标段落与 diff，并采用 CAS。版本冲突先重新比较，不盲目覆盖。整文件 replace 必须有清晰范围和恢复记录，不能把片段更新扩成全文件覆盖。

规则强制级别升级需经过规则影响分析和验证；单次成功经验不得自动升级为所有任务的强制规则。维护脚本出候选清单不等于发布。

## 5. 更新、撤回和锁定

新方案锁定实际知识修订/摘要；外部来源无法固定时标 unfrozen，按政策限制其用途。旧方案保留当时证据。撤回来源影响新检索的默认采用，并对能追溯的依赖发出待复核标记；没有依赖映射时明确影响范围未知，不宣称已完成全量传播。

本地内容、索引和远端备份各有版本；索引重建不能改变原知识状态。备份从一致性快照生成，不能热同步运行数据库/WAL。

## 6. 三条改进通道

| 通道 | 候选 | 生效要求 |
|---|---|---|
| 知识经验 | lesson、纠错、案例说明 | 来源、适用性、合并和审阅记录 |
| 技能/流程 | 重复步骤、模板或子流程 | 触发、输入输出、成功条件、实际回放与显式发布 |
| 代理/上下文 | 角色定义、知识装载或工具使用变更 | 固定对照任务、候选 diff、质量/成本评估和对应应用授权 |

只能读取当前获授权的历史范围，不为挖掘方便读取或外发全部聊天。候选写独立 staging，活跃规则/提示词/技能/开关不变。安装或发布权限独立于运行仿真权限；已有明确授权可复用，不重复询问。

评估须同时看科学质量、审查遗漏、恢复正确性和成本。减少 token 但漏掉关键检查的候选不得因更便宜而通过。真实模型效果需真实对照证据，确定性 mock 只证明管线行为。
