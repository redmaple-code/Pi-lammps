# 00 范围、术语与决策

## 1. 已确认范围

用户确认将通用化方案落实为开发规范与文档包。本轮交付包括模块边界、接口、领域包声明、状态规则、开发约束、迁移工作包与验收；不修改 `redmaple-agent/` 产品源码，不开发求解器或运行仿真。

目标系统必须支持：领域包选择/修改/组合、知识隔离与复用、工具能力绑定、可配置阶段图、检查和证据、运行监督、分析验收、版本与恢复、改进候选。跨域能力不能只用多个材料或多个 LAMMPS 模板证明。

## 2. 术语与身份

| 名称 | 定义 |
|---|---|
| domain pack / 领域包 | 一类问题的知识、模型、工作流、检查、计量与工具需求的版本化集合 |
| profile / 工具配置 | 将能力绑定到适配器和受支持工具，不包含机器秘密 |
| case / 案例 | 持续的问题身份；可含多个方案版本 |
| revision / 方案版本 | 冻结的问题、包、流程与输入设计；科学条件变化产生新版本 |
| stage instance / 阶段实例 | 某方案内、某分支/迭代中的具体阶段 |
| attempt / 尝试 | 阶段实例的一次生产或修订过程，不是新方案 |
| operation / 操作 | 一次有副作用的调用意图，具有稳定幂等身份 |
| run / 运行 | 固定输入的一次真实求解；一个研究活动可含多个运行 |
| study / 研究活动 | 扫描、收敛、校准、重复试验等有计划的一组运行 |
| artifact / 工件 | 有内容身份、类型、来源、生产者和依赖的文件/数据/记录 |
| review / 审查 | 针对固定输入闭包和规则版本的独立检查回执 |

“领域”“求解器”“任务模板”必须独立：一个领域可支持多个求解器和任务；一个求解器可支持多个领域。

## 3. 设计决定

| ID | 决定及理由 | 对旧方案的关系 |
|---|---|---|
| DEC-001 | 保留通用内核、领域包、适配层；宿主通过公开端口接入 | 延续原三层原则 |
| DEC-002 | 内核调度声明式阶段图；DAG 加有界迭代节点，不固定 WF 编号 | 原 WF-00…05 成为 LAMMPS 工作流 |
| DEC-003 | 采用 manifest 及具名资源分类；旧七声明经显式映射导入 | 文件名不是永久 API，原字段语义必须保留 |
| DEC-004 | 新规范不普遍强制本地案例；各包声明参考证据政策 | LAMMPS 的至少一份本地实读案例要求保留 |
| DEC-005 | 必需证据、门禁独立性、权限和真实执行证据不得被包降低 | 原有强制检查继续有效 |
| DEC-006 | 修订/修复上限是策略，内核维护不可逃逸计数 | LAMMPS 连续三次的两套计数分别保留 |
| DEC-007 | 包/工具/知识/流程版本在方案规划时锁定；更新用于新方案 | 禁止运行中隐式热替换 |
| DEC-008 | 单体模块化先行，不要求微服务；不预先绑定数据库新产品 | 复用现有 Node/Pi 生态，隔离宿主依赖 |
| DEC-009 | 真实求解、数值验证、模型验证、任务验收独立 | 扩展原 completed 与 D7 分离 |
| DEC-010 | 使用能力端口与可信扩展；配置不能执行表达式代码或更改状态机 | 延续禁任意 hook 绕门禁 |
| DEC-011 | 新案例用通用目录；旧案例经布局适配器读取，不强制迁移文件 | 原目录只作为兼容布局 |
| DEC-012 | 模式控制交互频率，授权决定行动；已有授权可复用 | 明确解决旧 auto 禁问与必要决定冲突 |

这里的“确认”指用户已确认总体方向；具体字段、编号和模块切分是本轮工程细化，不冒称用户逐字段审阅。

## 4. 规范与旧基线冲突时

1. 通用机制以本包为目标规范；旧 LAMMPS 科学职责和强制检查由专属包保留。
2. 旧 MIG 项涉及通用化调整时，使用 [legacy-mapping.json](legacy-mapping.json) 中的明确说明。
3. 缺失原文/文件不是删除义务的理由；缺件登记为迁移阻塞，不能用新示例补造原始依据。
4. 验收中若通用规则与领域规则存在真实冲突，返回 `POLICY_CONFLICT`，停止受影响操作，给出双方版本和位置。
5. 已有案例不得因为规范更新而获得追溯性的 PASS。必要变更创建新方案并重评受影响记录。

## 5. 当前不承诺

不承诺任意模型自动跨域转换、求解器无损互换、所有尺度共享正确模型、所有仿真自动达到科学目标。尚无用户给定的吞吐量和延迟目标，不能写入未经测量的性能数字。

知识来源授权、商业工具许可证、真实数据和求解器安装是具体部署依赖，缺失只阻塞依赖它们的阶段；不阻止编写契约和实现不依赖外部服务的内核。
