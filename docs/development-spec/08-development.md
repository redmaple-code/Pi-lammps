# 08 开发、测试与变更规范

## 1. 仓库与语言基线

现有产品位于 `redmaple-agent/`，ESM JavaScript，`package.json` 要求 Node ≥22.19.0，当前锁定 Pi 依赖为 1.5.0。既有基线 HEAD 为 `25dec99af3b5c3a5d06ddf5c788b89cd5c5d36df`。这些是本轮读取的基线，不承诺以后自动跟随 main。

新增仿真模块建议使用 TypeScript＋JSON Schema，在 Node 上运行；保留 Python 等科学工具生态。实际开工先检查当时仓库指令、工作树和版本，遵守已有约定，不为本次文档范围创建语言工程。

## 2. 实现要求

1. 边界输入必须先校验结构再校验语义；错误包含定位、实际版本、可恢复动作，不能吞错后返回成功。
2. 状态逻辑使用显式命令/事件和可测试的转换；模型输出只能成为候选输入或回执，不能执行任意状态代码。
3. 每次外部副作用都有稳定 operationId 和请求摘要；预算/截止时间传递到适配器。
4. 凭证、机器路径与科学参数分开配置；不把本机秘密写入包或测试 fixture。
5. 内容不可变，改动生成新版本；计算输入、检查回执和原始数据不得被修复脚本覆盖。
6. 新依赖说明用途、许可、版本、维护风险和替代方案；锁定依赖，不顺带升级无关工具链。
7. 注释解释非显然约束、单位和状态语义；不为简单赋值堆注释或照抄本文。
8. 领域分支只允许在领域工具/规则实现中，不能出现在内核决策中。公共机制变化需用不同领域案例证明。

## 3. 测试分层

| 层次 | 证明什么 | 不能证明什么 |
|---|---|---|
| Schema/静态 | 字段、枚举、引用结构、语法和依赖方向 | 真实流程能跑、科学规则正确 |
| 单元 | 三值条件、状态转换、计数、失效、单位/格式转换 | 外部求解器兼容性 |
| 契约/集成 | 生产者与消费者、CAS、outbox、适配器状态和格式 | 现实模型可信度 |
| 故障恢复 | 提交后崩溃、重复回执、未知结果、取消、并发冲突 | 所有工具都 exactly-once |
| 真实工具 | 指定环境中的实际调用、输出和解析 | 跨域科学有效性 |
| 科学/系统验收 | 目标任务、数值与统计方法、模型/指标证据 | 未运行或不适用领域的正确性 |

测试使用可控时钟和明确发送状态处理超时，避免用极短墙钟阈值制造脆弱断言。测试应检验外部行为/不变量，不能只镜像实现。没有相应环境则记 notRun/notVerified，不能用 mock 改记真实通过。

## 4. 现有命令与已知基线问题

现有产品的测试命令是 `npm test`，定义为 `node --test --test-concurrency=1 test/*.test.js`。既有报告记录 79 项中 75 通过、1 失败、3 跳过；本轮文档工作不重跑这组产品测试，也不改变该结论。

已知失败涉及预算耗尽与发送后结果未知的优先级；实现前应区分发送前取消和发送后未知，不能为通过断言清除未知调用。详见[基线核验](../基线核验.md)。

新增模块目前没有 build/lint/test 命令；开工时再建立实际脚本和 CI，文档不得将计划命令写为已可用。

## 5. 变更与评审

实现 PR/变更记录必须含需求 ID、问题和改变后的行为、契约/数据影响、实际验证及限制。接口/默认值/状态语义变化先分析所有消费者；破坏兼容变更提供版本并存、迁移和回退。

小的内部可逆实现调整由开发自主处理；目标、权限、数据含义或成本范围发生变化时记录产品影响，再按已有授权处理必要决定，不人为增加每步确认。

回退不能仅回滚指针并声称数据已恢复。数据库、工件、工具版本和包锁分别说明可恢复范围；备份恢复需实际核对，不删除失败证据。

## 6. 完成定义

一个工作包完成需：行为有可观察证据；契约和文档一致；相关正常/反例/故障检查通过；缺口有范围与责任；实现 commit/环境/证据可定位。整体交付仍需 [10 验收](10-acceptance.md) 的跨领域真实案例和历史迁移要求。

开发自测、技术就绪和用户产品验收分别记录。本次规范交付不代表其中任何产品状态已经达成。
