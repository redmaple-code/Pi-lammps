# 项目实施计划、责任与风险

工程修订 MD-1，2026-11-17。依据 project-manager 的目标/范围/依赖/责任/证据分离要求维护。本轮范围为细化开发文档；没有启动产品实现、实际仿真、部署或发布。

## 1. 目标、范围与承诺

交付一套能分配给开发者的模块说明：接口与数据所有权明确、依赖可排序、每项需求有主责模块和验收去向，保留 Pi 独立优化空间。沿用 MIG-001–092，以及工作区现有跨领域规范 GSF-001–024，不另造第二套需求正文。

本包21个模块、63个实现任务是规划拆分。工作区未发现既有 project-to-act 或 PM state.json，本轮不为使用 project-manager 强建账本；未启用 DELIVERY-1，不补造阶段批准/验收回执。项目层只维护范围、依赖、风险和必要引用。

文档完成、实现完成、技术验证、产品接受分别记录。当前各产品任务为planned，implementationStatus=notImplemented，verificationStatus=notRun；具体人员、开始日期、承诺日期未分配。不能把文档覆盖116项说成产品完成116项。

## 4. 推荐实施顺序与可并行工作

1. 先核当时工作树/版本、现有指令和 source gap；开展 DEV-01-1/2 与 DEV-18-1，建立可执行测试入口。外部科学数据未齐不妨碍此步。
2. 完成契约后推进 MOD08 的状态存储、MOD19 的包解析、MOD02 的角色接口。MOD10/21可先准备真实基准和来源；这不是启动真实计算的授权。
3. 接 MOD05/06/04/03，先以受控假端口验证四门、跨域图、计数和崩溃恢复；同时MOD11完成最小本地监督器，不能据假端口关闭真实执行验收。
4. 早期纵切采用一个微观近例，同时验证宏观/事件数据契约，尽早暴露抽象写死问题。接MOD09/14，不等最后才补单位、窗口和真实图核验。
5. 完成知识和历史导入、远程执行能力、三范式真实基准；再开展研究活动/耦合与技能/代理改进。MOD13可先完成候选隔离，不必等所有科学工具上线。
6. MOD17贯穿准备测试计划，最后收集跨模块真实回执；MOD15负责用户入口和明确完成范围。全部必需项闭合后才讨论完整产品发布接受。

关键依赖链之一：契约→状态→工件→证据→门禁→阶段→真实执行/分析→领域验证→集成接受。包解析与基座优化可并行；具体执行阶段由任务DAG约束，不按文档编号串行施工。模块的第1任务是接口/fixture准备，可以在第2任务依赖未就绪时独立开展；任务DAG为实际开工下界。

这些是岗位建议，不是已落实的人力。每任务的assignedPerson保持null，实施分派时填真实承担者；角色可以由同一人承担多个，但同一科学产物的独立审查不能省略。

## 6. 估算、承诺与日期

模块估算合计 **73–119 人日，约15–24人周**（按5工作日/周），包含模块实现与专属测试；MOD17仅计集成验证工作，避免把单测重复估算。假设开发者熟悉Node/TS/Pi，领域人员能提供适用规则/基准，已有可用科学工具环境。真实模型调用费用、HPC排队与计算墙钟、缺件恢复等待、商业软件获取不计入这些人日。

这是比上一轮12–20人周更细的预测区间，**不是承诺日期**。差异来自逐模块拆分，以及工作区新增通用规范明确要求的真实宏观/事件、包组合、研究活动/耦合验证。原LAMMPS迁移范围没有削减。完成WP-01及最小纵切后，用实际吞吐和缺件情况再估；不能用生成文档速度推算代码工期。

当前无外部硬截止、无批准的人力容量，故不虚构甘特日期。两条开发线可按“契约/内核”和“基座/工具”并行，领域审查同步供给；不能直接把人日除以人数当日历工期。预测发生变化仅更新受影响模块、依赖和风险，不改写已取得历史证据。

## 8. 开工与收尾检查

开工所需最小包：实际任务ID、需求引用、模块/集成契约、可信源码基线、前置任务回执、必要外部资产。缺不相关环境不阻塞独立任务。

每个任务收尾提供实现commit、实际文件/符号、契约/数据变更、实际命令/结果、未验证项、消费者交接和回退说明。planned测试路径只有实现后才能改current。技术自测与产品接受分别留事实；不根据文件数量推导进度百分比。

本轮交接：阅读[总入口](README.md)→选模块→依赖tasks.json→按需求追踪表核专属验收；尚未授权本轮执行这些实现任务。若下一轮要求实施，应直接从可开工任务推进，不重复询问已授权内容。
