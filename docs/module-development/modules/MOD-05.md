将文件与数据绑定到不可变内容、版本和生产链；支持二进制、大轨迹、旧目录和最小修改。

- 建议责任岗位：存储与工件开发。具体人员未分配；不表示已启动代理或已作人员承诺。
- 拟议代码边界：`simulation/packages/artifacts`。
- 当前依据：redmaple-agent/src/workflow-verification.js；src/workspace-tools.js；原案例布局。
- 需求主责：MIG-002、MIG-033、MIG-062、MIG-064。
- 通用需求主责：GSF-005。
- 实施依赖：[MOD-01](MOD-01.md)、[MOD-08](MOD-08.md)。
- 依赖是开发成果依赖，不是允许相互 import；代码依赖必须服从 [共享集成契约](../集成契约.md) 的单向端口注入。
- 估算：3–4 人日，包含本模块实现与专属测试，不含外部等待；以 [项目实施计划](../项目实施计划.md) 为估算解释和排期依据。

## 2. 文件与职责拆分

- `publish.ts`：暂存/校验/原子发布
- `closure.ts`：依赖闭包和目录摘要
- `registry.ts`：工件引用/状态
- `layout-legacy.ts`：原目录适配
- `test/artifacts/*.test.ts`：按文件名称承担上文所述职责；实施前确认实际目录

新文件与测试路径均相对上面的模块边界；若跨两个包，实施时在任务回执标注准确路径。现有基座文件只能作为明确列出的改动点，不能把整个基座复制进领域包。

## 4. 实现机制与不变量

文件摘要按原始字节流计算；路径/长度/摘要列表排序后计算closure摘要，记录算法版本。结构、势、include、脚本与环境规格在运行前闭合。大对象以manifest和内容地址引用，JSON不内嵌dump。暂存完整写入、fsync和校验后不可变发布，最后由K6登记引用。输入raw保留原样；竞争方案分revision，参数扫描分run。新布局跟规范，旧versions/vNNN布局通过只读适配。

## 5. 数据、存储与所有权

ArtifactRef与ArtifactMetadata分离；依赖图节点使用不可变artifactId/digest而非可变路径。locator可迁移但内容身份不变；绝对外部路径单独受授权根限制。失踪工件标missing，不能同名补空文件。

不复制其它模块权威状态。跨库操作使用持久操作意图及回执，不声称外部调用与本地事务原子提交。关联元数据必须使用真实输入/版本，不能从“最新文件”猜测。

## 6. 主路径与异常处理

1. 读取基线、当前revision与授权目标，生成最小候选diff。
2. 流式hash与依赖遍历，检查循环、路径逃逸、符号链接与missing。
3. 发布新工件并登记依赖；由K1根据ChangeSet决定失效范围。

异常与恢复：无唯一case/revision拒绝写作；摘要不符ARTIFACT_CHANGED；半写入不发布。跨卷rename不能假定原子，应在目标卷暂存再发布。

日志仅记录身份、版本、状态、诊断位置和证据引用；敏感源正文、凭证与全历史不进入通用日志。时间/数量等测量保留单位。性能先采基线，尚无已承诺吞吐量或延迟目标。
