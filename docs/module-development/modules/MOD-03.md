## 4. 实现机制与不变量

阶段图无环，循环只能由显式有界 iteration 节点展开。分支 unknown 保留等待原因，不走默认免检边；join 声明等待全部/选中分支，不把 failed 当 skipped。仅执行/分析/绘图入口继承各自证据前置，检索不造案例。修订计数绑定 case+revision+逻辑阶段，修复计数绑定持久 repairChain；换 session/attempt 不清零。guided/semi/auto 只调交互频率，授权来自独立 UserDecision。回退记录失效闭包，不删除旧记录。

## 5. 数据、存储与所有权

阶段实例包含 graphNodeId、branchPath、iterationIndex、attemptId、status、dependencies、activeReceiptRefs。阶段细分状态与领域判定分离；实际枚举采用规范04，未完成模型任务不能变成 reviewed。

不复制其它模块权威状态。跨库操作使用持久操作意图及回执，不声称外部调用与本地事务原子提交。关联元数据必须使用真实输入/版本，不能从“最新文件”猜测。

## 6. 主路径与异常处理

1. 识别 TaskSpec.scope 和可信已有工件；解析领域流程生成计划。
2. 读取已校验回执，纯 reducer 计算候选事件和 outbox；K6 做 CAS 提交。
3. 影响分析或停止条件到达时暂停对应分支，返回下一责任方与最小补做范围。

异常与恢复：图环/悬空引用为 SCHEMA_INVALID；未知条件等待材料；授权缺口只阻塞相关节点。重复命令不得推进第二次或多计失败。

日志仅记录身份、版本、状态、诊断位置和证据引用；敏感源正文、凭证与全历史不进入通用日志。时间/数量等测量保留单位。性能先采基线，尚无已承诺吞吐量或延迟目标。
