# AI002–007 工程修订

工程修订 ROLE-2，2026-11-18。

## 当前范围与已确认决定

本轮实施 AI002、AI003、AI004、AI006、AI007。AI001 按用户接受的误差处理，AI005 暂缓。

用户确认复用 WorkflowRunner、SQLite 和 RedMapleRuntimePort，角色使用 aispot-ds 的 deepseek-v4.1-flash。生产和审查使用独立会话，13 个原角色按任务条件调用。Python、LAMMPS 和 OVITO 通过宿主工具执行。

用户确认分层推进。几何、单位、输入合法性和执行前置检查失败时停止对应执行。缺少实验或收敛证据时，允许有明确限制的探索计算，分别报告流程、数值验证、模型适用性与任务达标状态。

用户选择一个真实磨削算例及恢复测试。本轮科学比较协议记录缺失的收敛和匹配实验数据，并检验数值比较机制的通过、超限、边界、缺数据、条件不匹配和单位错误分支。

## 接口和实现

### AI002

result-state.js 对结果快照绑定方案版本、包锁、案例状态、阶段状态、attempt、生产身份、输入输出工件和审查回执。读取时核验参数、工具快照、协议、工件字节及审查来源。失效清除下游 outputSlots，保存历史阶段对象。旧完成案例从当前阶段工件重建结果，活动历史案例在外部操作已对账后升级剩余阶段。

awaitingInspection 是持久停点。图片核验绑定当前快照和实际工件。失效、取消、重绘和重新分析会使旧结果快照失去当前有效性。

执行阶段使用 attachOperation 建立唯一操作。父流程中断后查询并等待原 worker，复用确认结果，经恢复角色形成产出回执，使用 recoverProduced 推进阶段。远程模型结果未知与宿主工具结果分别记录，恢复会保留原未知记录及宿主副作用对账依据。

### AI003

grinding-workflow.js 在正式 grinding/run/resume 和 /sim-grinding 入口装配角色处理器。处理器按阶段 ID、角色、capability 的顺序解析，宿主身份贯穿 start、实际角色会话与审查。

simulation_stage_run 提供限定于当前阶段的工具参数，返回实际候选工件和硬检查。设计角色可以选择受支持的参数并冻结协议，输入角色可以提交完整输入文本。角色通过 simulation_artifact_read 实读候选，通过受约束的 simulation_artifact_publish 发布结构化阶段产物。

case-librarian 和 paper-researcher 为方案论证提供案例和资料覆盖判断。analyst 与 reasoner 用于实际失败诊断及有证据的输入修复，设计性故障记录为需要新方案修订。recordKnowledge 配置启用 kb-coordinator、kb-curator 和独立 kb-reviewer，候选经既有知识服务完成提议与裁决。

同一问题默认最多两轮自动修订，状态与调用预算持久化。恢复阶段复用已通过前置工件。模型调用仅允许配置中的 aispot-ds/deepseek-v4.1-flash。凭据通过 twin inject 注入，配置和交付文件仅记录环境变量名。

### AI004

delivery-status.js 按本轮五项修复汇总回执。通过记录需要当前源码摘要、执行时间和证据引用，缺项、失败及过期验证得到 partial。当前工程记录与历史规划快照通过引用关联。

### AI006

审查按阶段登记 current-stage 与 method-reference，绑定来源摘要。每个必需命题具有允许来源集合及冻结的来源摘要，审查提供真实读取回执、引文、支持或冲突判断和适用理由。引文匹配只归一化空白与换行，来源字节摘要和实读范围保持可核查。门禁检查引文属于实际读取范围、来源属于对应命题、读取身份属于该审查者。冲突和关键命题缺证据阻止放行。

宿主硬检查自动并入审查，模型提交同名检查会被拒绝。审查绑定生产对象、attempt、证据政策和适用性政策。证据内容的科学相关性由独立 DS 审查判断，程序验证来源、引用与政策约束。相同模型的独立会话仍可能存在共同判断偏差，关键单位和运动参数另由程序复核。

### AI007

validationProtocol 在设计阶段冻结，设计输出经独立审查后才进入求解。定量比较记录物理量、单位、方法、采样、选择范围、参考工件、参考条件和绝对容差。参考条件或单位不匹配时返回 cannotCompute，容差附近返回 borderline。

五项集成指标保存 integration 结果。数值、模型和目标比较独立计算，已有数据不足以比较时返回具体原因。运动核查从真实 grinding.csv 重建时间步、速度及行程，速度按 1 Å/ps = 100 m/s 换算。日志 ERROR/WARNING 扫描覆盖全部行，报告另存抽样展示范围。

## 联调问题记录

- 首次审查在 32768 上下文预算和 16384 输出预留下触发上下文上限。角色输出预留调整为 8192，并保留失败会话。
- 早期审查工具只声明 checks 为对象，模型曾把 extensions 放在根级、把 observations 写成字符串。已明确嵌套 schema。
- 已知前置失败原先被 Pi 视为未知副作用，导致 Run has stopped。适配层将明确的领域错误映射为 knownOutcome，并保留真实未知状态。
- 非设计角色曾传入空 parameterOverrides。工具参数现在按阶段声明，空修改按无变更处理。
- 资料角色曾使用 application/json 作为工件类型。新调用明确约束 stage-packet，旧 JSON 回执按内容契约读取并保留原始类型。
- 新增恢复测试初版遗漏 plan.directory，已修正测试夹具。
- 默认每个角色累计 120000 token 在多轮实读时提前耗尽，角色适配配置增加可调整的累计 token 预算，默认 512000。
- 审查者在修正引文时可能提交多份回执。初版恢复取第一份回执，且错误地要求 BLOCKED 回执也满足通过条件。现按最终回执推进，历史回执完整保留。
- 开发联调将本算例的调用上限从 80 调整为 128、160、192、224、256，保留已使用次数和调整原因。生产默认上限继续由配置决定。
- DS 输入角色曾把工具的空参数对象写成 inputText="{}"，随后又提交仅含初始化段的占位脚本，使用 substrate.data 和错误的周期方向，缺少势、动态过程及验收输出。硬检查阻止这些候选进入求解。
- 初版候选工具直接覆盖 inputs/in.grinding，导致坏候选影响下一次恢复。现使用不可变候选与独立基线工件，允许最多两次输入候选修正，保留候选历史。求解采用通过审查的工件闭包，并同步已批准的脚本显示副本。
- 原 fix-print-command.txt 是手册目录页。修订来源使用 LAMMPS stable_2Aug2023 的正式 doc/src/fix_print.rst，保留旧文件作为历史错误来源，当前审查绑定修订后来源的摘要。
- 输入审查的长推理与资料读取超过原 32K 客户端预算。审查使用阶段任务说明、带原始设计引用的摘要、可按需读取的原角色指南，并预留最多 16384 输出 token。当前工作区配置为 40960，上下文自动压缩预留 18432、最近内容保留 8192，已沿用并验证配置加载。服务模型目录未提供容量字段，此值是客户端预算，真实调用记录说明实际请求的验证范围。
- 审查重试按稳定的运行时配置摘要计数，最多两次自动重试。配置摘要包括模型、上下文预算、输出预算、任务说明与审查绑定，历史配置下的失败完整保留。
- Node/Python 出现 TLS 连接重置，cURL 经相同本机代理调用同一模型成功。加入可配置的 cURL 流式 fetch，头部和 JSON 通过 stdin 传入，支持响应流、HTTP 错误及取消。基座补充宿主 fetch 配置向实际模型传输的传递。实际密钥保持 twin inject 注入。
