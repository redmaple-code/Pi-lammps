# 上下文与技能注入专项检查

2026-11-18。按用户要求将 Pi-agent 客户端窗口设为 40K，并检查上下文压缩与技能注入。

## 配置

运行时配置使用 40,960 tokens 的窗口，单次输出上限为 16,384 tokens。自动压缩启用，reserveTokens 为 18,432，keepRecentTokens 为 8,192。阈值检查在当前占用超过 22,528 tokens 时触发，具体切分遵循原生 Pi 的消息与工具调用边界。

## 发现与修复

| 问题 | 影响 | 修复 |
|---|---|---|
| 原压缩预算用 systemPrompt 文本估算，遗漏独立工具定义 | 摘要生成成功后，下一请求仍可能超出窗口 | 使用规范化的当前系统消息，计入工具定义、技能目录、近期消息与下一次输出预留，合并系统更新时避免重复计数 |
| 摘要路由模型的容量被用于下一次回复的容量校验 | 摘要模型与回复模型容量不同时可能接受过大的检查点 | 保留与发布预算使用下一次回复模型的窗口，摘要生成仍受摘要模型自身输出上限约束 |
| 技能目录公开了已登记文件，但工作区路径规则阻止读取外部技能 | 模型可以看到技能名称，却无法按目录读取其正文与参考文件 | 向 read 提供资源加载器登记的技能根目录，只读访问继续通过真实路径边界检查 |
| 压缩提示未明确要求保留技能引用 | 后续工作缺少重新读取技能的定位信息 | 摘要提示加入已调用技能名称、源路径和重新加载要求 |

技能目录的名称、说明和路径由原生 Pi 进行 XML 转义。启动上下文包含目录，正文通过 read 或 /skill:name 按需加载。系统技能目录在压缩投影中保留。技能正文进入历史后遵循正常压缩流程，后续使用应按保留的来源重新读取。正文摘要由模型生成，具体内容保留质量仍需结合任务核验。

权限回归覆盖登记目录内参考文件、未登记邻接文件、越界目录链接和外部写入。外部路径读取例外仅提供给 read，宿主 authorizeTool 回调仍在权限判断之前执行。
