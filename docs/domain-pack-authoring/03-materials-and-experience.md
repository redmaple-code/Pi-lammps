# 03 行业案例、规范与经验注入

## 1. 可接收材料

支持行业/企业规程、标准条款、报告、输入与输出、实验/生产数据、失败日志、培训材料、操作手册、论文、用户口述和已有知识库导出。每次注入形成批次，保留贡献者、资料归属、读取范围、引用和可使用/导出范围。

来源可先登记为待取得。资料没有完整原件时，记录用户所能提供的身份和可访问内容，例如“某次项目复盘中的转述”。口述以说话者、日期、原话范围和后续修订作为来源，后续有文件时增加 supports/challenges 关系。

## 2. 资料接收流程

登记原始材料→校验身份/修订→解析与覆盖说明→选择相关片段→生成提取候选→追问→标注和采用→入库→回查。

原始资料按收到的版本保存。重复文件可共用内容对象，批次与贡献记录分别保留。相似文字、同一案例的不同报告和转载保留同源关系。PDF/OCR、表格、图像和程序输出记录解析方法、页/表/单元格/帧/行位置及不确定处。

资料收到了、资料读过哪些部分、用户认可如何使用，分别记录。读取失败时先保存资料身份和缺口，其它可读资料继续整理。

## 3. 经验访谈

经验采用“场景→判断信号→选择→动作→实际结果→原因解释→边界/例外→可复用动作”的表达。经验卡可以边问边补，用户不必一次填写全部字段。

| 追问角度 | 可用问法 | 影响的设计 |
|---|---|---|
| 场景 | 当时做什么，体系/设备/软件版本和工况是什么？ | 适用范围、任务路由 |
| 信号 | 哪个现象让你决定调整？怎样识别？ | 检查触发、失败诊断 |
| 选择 | 你比较过哪些做法？为何采用这一项？ | 方法选择和备选路线 |
| 动作 | 实际改了哪个参数、步骤或边界？改前改后是什么？ | 参数与流程候选 |
| 结果 | 实际观察到了什么？有数据或报告可回查吗？ | 案例事实和评价口径 |
| 归因 | 你认为为何有效？有没有同时改变其它条件？ | 机制假设与判别任务 |
| 例外 | 什么情况下失效？是否有反例或不能确定的情形？ | 边界、反例和验证 |
| 复用 | 下次遇到什么条件应提醒谁做什么？ | 可检索经验与工作流入口 |

将“实际观察”和“原因判断”拆为不同知识单元，分别支持。用户尚不能确认原因时保留候选解释。一个失败案例仍可提供有价值的观察、诊断路径或不适用条件。

## 4. 行业案例复原

案例至少覆盖当前任务所需的情境、基线、问题、判断、修改、结果和限制，并链接实际材料。对有资料支持的项目路径，可进一步复原 hypothesis、construction、mechanism、validation、finding、transfer。

每项填写 documented、gap 或 proposed，标明原报告、后续评价、用户亲历或当前归纳。作者/操作者未记录的发现历史保留未知。原案例的数值、模型和参数具有本案例作用域，提炼可复用操作时单独说明保留条件。

相同案例产生多份材料时共享 caseId/originGroupId。多个案例比较的重点是同一决策在什么条件成立、怎样识别例外、怎样验证迁移。单例经验可供有范围的提醒，扩大为通用规则需额外依据和采用决定。

## 5. 规范与条款

规范材料记录发行方、编号、标题、版本/发布日期、适用期核查、行业/地域/对象范围、条款定位和原文。条款分离 normative、recommendation、informative，并保留原文的义务用语。

从条款到当前包检查，还需补充以下内容。

- 当前任务为何适用，哪些实体/工况触发。
- 检查对象、执行方法、所需输出和证据。
- 数值阈值、单位、容差以及该阈值适用的测量方法。
- 例外、替代合规方法、冲突与有效版本。
- 用户以什么身份决定采用，采用为外部义务、项目合同要求还是本地实践。

企业选择采用某条建议后，可以形成 localPolicy。其来源属性和外部效力保持原始含义。正式标准的现行/废止/替代状态需查到明确依据，无法核对时记 unverified 并说明当前用途。

将条款作为外部强制义务时，记录发行主体、效力和当前适用版本的依据。用户选择的项目实践则记录项目采用决定及范围，两者在执行提示中显示各自身份。

## 6. 注入后的即时回馈

用户提交一份案例后，系统先返回资料身份、可读范围、最相关片段、候选标签和少量关键问题。用户确认其含义与适用条件后，返回知识单元、采用回执及检索样例，展示它将改变的流程/检查/参数位置。

若资料只是背景，按用户目的登记为背景资源。若材料与已有结论冲突，建立争议记录，分别保留版本、条件和证据，围绕会影响当前决定的差异追问。

## 7. 最小覆盖的确定

覆盖来自用户要支持的决策。例如有限元瞬态任务可能需要质量/边界/阻尼/载荷与精度经验，小分子对接任务可能需要准备、位点、控制与评分解释经验。覆盖表逐项列出当前依据、适用条件、反例和缺口。

材料数量可随任务变化。缺少现成行业标准时，明确哪些判断依据用户实践、公开方法或待验证假设，并继续完善其余设计。
