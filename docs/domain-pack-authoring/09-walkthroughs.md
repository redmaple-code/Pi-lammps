# 09 完整引导演示

本章为制作过程示例。用户材料、采用决定和科学结果将在实际会话中取得。这里描述期望交互及产物，帮助开发者和领域人员检查工具行为。

## 1. 有限元动力学的经验入口

| 步骤 | 系统给用户的引导 | 用户可提供的内容 | 系统形成的产物 |
|---|---|---|---|
| 定任务 | 这套包先支持哪种动力学分析，结果将用于什么判断？ | 实际岗位、对象、交付或既有项目 | scope draft，已有回答直接复用 |
| 找代表案例 | 哪个项目最能说明你们平时怎样建模或判断结果？ | 项目报告、输入/输出、复盘或口述 | source/batch 与资料缺口 |
| 深挖经验 | 当时出现什么现象，让你决定改设置？ | 实际异常、原参数、改动及结果 | observation 与 practice 候选 |
| 查判断依据 | 你们怎样判断时程、频率或应力结果可用？ | 行业规程、试验、内部检查或专家经验 | clause/metric/check 候选 |
| 补条件 | 这条经验用于哪些单元、材料、频带和软件版本？哪些情况失效？ | 已知适用范围、反例或未知项 | conditions、exceptions、gaps |
| 对照打标 | 这些片段是否涉及瞬态、阻尼、采样或边界？哪几个标签符合你们的用语？ | 标签修订或已有行业词汇 | 建议/已采用标签及定义 |
| 采用与入库 | 这条内容先作为项目提醒、包设计依据还是待研究问题？ | 使用方式、批次采用或暂缓 | 决定和对应知识修订 |
| 包设计 | 这条经验应在哪一步提醒，需要什么输入和检查证据？ | 实际流程/岗位动作 | workflow/check/metric bindings |
| 验证 | 哪个正常项目和失败项目适合验证新步骤？ | 已有案例或待征集清单 | 验证计划和设计准备度 |

若用户只讲“调整阻尼后结果变好了”，先登记其观察，追问阻尼定义、其它同步变化、评价方法和证据。原因尚待分辨时，可先采用为“遇到相似异常时复核阻尼设置”的诊断提醒，再开展对应调研或验证。

## 2. 小分子对接的规范入口

| 步骤 | 系统给用户的引导 | 用户可提供的内容 | 系统形成的产物 |
|---|---|---|---|
| 定用途 | 你们主要用对接解释姿态、候选排序还是评估筛选方法？ | 实际用途和使用者 | 任务与可报告结论范围 |
| 看规程 | 哪份准备/质量规程在你们项目中采用？ | 企业SOP、发表方法、工具手册 | source 和适用性候选 |
| 定条款 | 其中哪一条会决定配体、受体或控制试验怎样准备？ | 条款位置与原文 | fragment、clause和候选标签 |
| 找案例 | 有没有因准备状态、位点或评分解释产生返工的项目？ | 成功/失败输入、分析或口述 | 案例复原和失败条件 |
| 补隐含经验 | 当文件有多个状态或软件版本不同，实际怎样处理？ | 行业习惯、例外、检查动作 | practice与条件；未知项待核 |
| 调研对照 | 需要先核对哪个工具支持、概念或验证方法？ | 用户指定问题或公开资料范围 | researchQuestion与来源候选 |
| 对照与采用 | 这份规程在当前项目哪些情况适用？你希望采用哪些标签和检查？ | 适用范围、决定或修改 | annotations、decisions、知识选择集 |
| 编排与验证 | 哪些输入/输出能证明准备和控制步骤按要求完成？ | 证据清单、现有基准 | 工作流、输出闭合与验证计划 |

当内部规程与公开教程采用不同方法时，先列出工具版本、体系、目的和条件差异。由用户决定当前项目采用范围，调研帮助核查依据，争议与替代方案继续保存。

## 3. 一次注入的可见结果

假设用户在工作台提交一份项目报告。系统先显示接收身份、读取页段和解析问题，再显示三类可处理对象。

| 对象 | 用户操作 | 系统效果 |
|---|---|---|
| 资料标签建议 | 采用、改名、指定已有词汇、拒绝 | 保存标签修订和赋值依据 |
| 经验单元候选 | 改条件、补结果、添加反例、选择用途 | 保存对应知识修订和决定 |
| 包设计影响 | 选择关联步骤、要求补调研、暂缓 | 新建DesignBinding或待办 |

结束本轮时提供可回查的来源→片段→标签→知识→用户决定→包设计链，以及“下一条最需要补的经验/规范是什么”的具体提示。候选仍能在工作台检索，执行上下文按有效采用用途取用。

## 4. 机器夹具的范围

[workshop-demo.json](examples/workshop-demo.json) 保存构造来源、待审标签和候选知识，mode 为 demonstration。它用于验证字段、引用、候选隔离和决定覆盖规则。实际导入工具应在 userSession 与 demonstration 之间显示清晰来源标识，实际用户决定由运行时记录。

[scoped-adoption-demo.json](examples/scoped-adoption-demo.json) 展示构造的范围采用过程，保留候选修订、决定和采用修订。示例中的知识用于 projectPractice，其 epistemicStatus 保持 unassessed。演示身份随全部记录保留。
