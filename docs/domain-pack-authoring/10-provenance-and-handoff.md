# 10 来源、衔接与交接

## 1. 采用的设计来源

本规范接续已有领域包、知识、数据/接口和科学验收设计。用户本轮增加主动引导、经验注入、案例与规范打标入库、存储选型待定的要求。

参考 scholar-apprentice 的领域知识模型、核心概念发现、研究路径复原、研究合同和经验回注。来源文件与本轮读取范围记录在 [参考定位表](sources/reference-map.json)。参考文件中的研究命令、实际数据库和具体研究目录作为其原有实现背景保留，本规范使用独立的制作会话与逻辑仓储契约。

## 2. 与现有规范的关系

| 既有内容 | 本规范的细化 |
|---|---|
| 领域包声明和资源格式 | 增加用户参与、资料与经验形成、采用与设计映射的制作过程 |
| 知识分类/裁决/合并 | 增加精确标注、受控词汇、口述来源、采用用途和引导问题 |
| 证据与来源契约 | 增加材料接收、读取覆盖、条款属性和知识单元关联 |
| 模型/流程/工具/指标 | 增加知识修订到包元素的 DesignBinding |
| 改进与反馈 | 增加每次取用经验的动作/效果回执，以及用户采用的新修订 |

现有开发规范入口与知识规范可继续参阅。[开发规范](../development-spec/README.md) [领域包](../development-spec/03-domain-pack.md) [知识规范](../development-spec/06-knowledge.md)

## 3. 当前实现的接入边界

本轮只读检查到 KnowledgeService 已有 ingest、search、read、propose、review、apply 和部分合并接口，KnowledgeBackendRegistry 已有 search/read/validate/propose 能力登记。当前数据模型以来源级 metadata、lesson、applicability 为中心。

新制作工具还需会话/问题、片段标注、词汇修订、多个知识单元、用户采用范围、标准条款和设计绑定等契约。可通过新服务与后端适配逐步接入。既有软件审查/权限约束由适配层映射，制作规则按本规范表达。

现有 review 接口要求 reviewer 与 curator 实例不同。AI 提案与用户采用可保留各自实际身份。用户自行整理并采用自身资料时，制作仓储记录其真实职责，通过明确的兼容接口扩展接入现有知识服务。

当前工程采用的具体数据库与历史库读取方式具有实施背景。本轮对制作仓储保留类型开放，后续根据能力契约测试选择实现。制作工具的新增接口按后续工作包实施。

## 4. 交付清单

交付包括制作规范、引导目录、数据交换 Schema、空白制作档案、资料/案例/经验/规范/审阅模板、构造演示、验收要求与来源定位。实际检查回执记录本轮解析、Schema、引用、链接和反例结果。

## 5. 完成与未验证项

文档和机器工件按本轮目标编制。当前行业资料征集、真实用户会话、工具实现、后端适配、实际入库及科学运行分别在后续制作/开发活动中验证。构造演示的决定与知识不进入实际用户知识选择集。

下轮使用可先恢复一个现有领域包，读取当前目标和资料，按 02 的引导流程选择当前缺口。当前总体方向与存储类型开放的要求已经明确，后续沿现有决定继续。
