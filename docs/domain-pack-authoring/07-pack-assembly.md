# 07 从知识到可开发领域包

## 1. 采用后的映射

每个包设计项关联明确的用户决定或已采用知识修订。AI 根据既定选择编排声明与文档，并显示来源映射、缺口和设计差异。

| 用户注入的内容 | 包设计落点 | 还需要确认 |
|---|---|---|
| 典型业务问题与交付 | scope、problem schema、任务路由 | 使用者、边界、交付责任 |
| 行业术语与分类 | vocabulary、任务字段和检索标签 | 定义、歧义、别名与适用语境 |
| 成功/失败案例 | knowledge cases、失败目录、验证案例 | 观察、归因、迁移条件、数据来源 |
| 操作经验与取舍 | workflow、checks、failures、templates | 触发、动作、输出、例外和失败处置 |
| 规范条款 | checks、measurement、输出闭合 | 版本、项目适用性、效力、测量方法 |
| 模型/参数依据 | models、parameter sets | 单位、条件、有效区间和校准 |
| 软件与运行经验 | tooling、adapter requirements | 版本、格式、资源、真实支持与验证 |
| 评价与验收经验 | metrics、acceptance、validation | 定义、参考、误差、统计和阈值来源 |

DesignBinding 保存 knowledgeRef、decisionRef、packElementRef、purpose、transformation 和 validationRefs。调整来源或结论时，沿绑定查看受影响设计。

## 2. 包制作的可交接结果

从用户确认范围形成 manifest 候选，领域内容按现有资源类别组织。知识库内容通过固定修订的选择集进入包，来源和采用记录随包引用或导出。可用文件摘要表达内容身份，独立字段记录行业适用性和验证状态。

已有小分子对接、有限元动力学包可作为方法与接口候选复用。制作工具展示其工程选择和待验证项，请用户根据实际业务选择采用部分，并注入自身案例、规程和经验。

导出的知识选择快照含 sessionRef、knowledgeRefs、sourceRefs、taxonomyRefs、annotationRefs、decisionRefs 和 DesignBinding。快照作为版本化 knowledge 资源进入 manifest，制作档案作为 template 资源或受控外部引用关联。现有 manifest 的 extensions 可用 `authoring.guide` 命名空间记录制作档案和选择快照引用，包资源摘要和原有 schemaVersion 继续按现有契约维护。

制作仓储与运行时知识服务通过映射器衔接，明确各知识字段、采用用途和来源状态的对应关系。新增字段保留在资源内容/扩展中，兼容能力由接入回执声明。

## 3. 一条经验变为流程

先将经验表述为有条件的操作，再逐项补齐 trigger、input、action、output、acceptance、onFailure、basisRefs 和 nonTransferable。这些字段连接到实际阶段、类型化工件和具名检查器。

以有限元经验为例，用户可能希望在某类时程异常时核查阻尼与采样。引导者需定位实际案例，追问异常判据、阻尼定义、频带、输出间隔和对照。用户采用后先形成“诊断分支”候选，具体阈值与修复动作依案例和验证填入。

由规范生成检查时保留条款位置、触发条件、阈值单位、测量定义、例外及严重程度的采用理由。工具能力缺失时建立开发任务，当前设计可继续描述其它已明确部分。

## 4. 设计审阅与验证

按用户用途检查正常案例、失败/例外、输入完整性、输出闭合、知识检索与包行为。需要独立科学验证的范围沿既有规范执行。用户确认了一项经验的使用方式后，软件仍需证明相应步骤按设计运行。

制作档案分别列出设计依据覆盖、用户决定覆盖、资料读取覆盖、工具接入、数值/科学验证和未完成项。每个指标都给分母和范围，关键决策缺口逐项可见。

## 5. 生成开发任务

每个待实现能力形成“目标行为、输入、输出、相关知识/用户决定、正常/反例、依赖、验证方法”。包内容编写可先完成，工具适配、解析器和语义检查分别交给开发工作。

用户可以在文档中直接修订已明确的内容。系统读取新修订、计算差异并更新绑定与待办，保留历史采用决定。新决定影响已发布内容时生成新包版本和迁移说明。

## 6. 发布与维护

打包前核对知识选择集、标签版本、决定、来源使用范围、内容摘要、包契约与验证回执。发布采用范围由当前用户或指定发布职责确认，已有明确授权继续适用。

包的后续任务返回应用回执，包含取用了什么经验、做了什么、结果是否支持其适用性以及证据。新反馈先形成修订候选，用户参与决定收窄、修正或保留的范围。
