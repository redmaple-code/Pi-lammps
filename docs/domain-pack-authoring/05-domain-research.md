# 05 调研与知识缺口补齐

## 1. 调研入口

在用户经验或行业材料留下重要缺口时，创建明确的 researchQuestion。每项说明当前设计决定、已有材料、待核问题、可能改变决定的证据、可用资源和输出形式。

调研可用于澄清术语、寻找模型前提、核对规范版本、复原代表案例、寻找相反证据、比较工具支持或设计验证。AI 可以在已授权资料范围内主动检索与分析，返回候选知识、来源和待决定项。

## 2. scholar-apprentice 的方法映射

| 参考方法 | 在制作活动中的使用 | 产物 |
|---|---|---|
| 目标与完成合同 | 把当前领域设计问题转为有范围和证据要求的调研任务 | researchQuestion、coverage、gaps |
| 核心概念发现 | 从权威资料、用户案例和失败中发现必要概念及混淆 | concept、aliases、条件和任务作用 |
| 领域知识模型 | 表达概念、判断、方法、经验、观察、资源及带类型关系 | knowledge units 与 task bindings |
| 研究路径复原 | 追溯前作、问题、原因假说、构造、验证、结果和边界 | case stages 与 workflow candidates |
| 反证与比较 | 主动检查例外、失效和其它解释 | challenges、争议和验证计划 |
| 经验回注 | 跟踪知识怎样改变具体任务，回收实际效果 | application receipts 与修订候选 |

本规范借鉴上述方法及可追溯原则，研究目标和存储接口沿当前制作活动定义。方法来源定位见 [来源与衔接](10-provenance-and-handoff.md)。

## 3. 调研步骤

1. 先检索已有包、用户资料、采用决定和相关失败，说明已有知识覆盖。
2. 按问题选择教材/权威讲义、正式规范、原始论文、工具手册和代表案例。
3. 核对实际读到的全文/章节/摘要/元数据，记录定位和独立来源组。
4. 抽取定义、条件、方法、操作经验和限制，并比较与用户实践的关系。
5. 查影响当前决定的反例与竞争解释，记录支持和挑战关系。
6. 返回可审阅的候选、原文位置、差异和采用选项。
7. 用户决定采用范围后，接入工作知识和包设计，缺口继续可见。

检索词和语料分类可随材料调整。用户已有的行业分解可作为起始导航，语料归纳结果保留其来源和用户组织视图的差异。

## 4. 覆盖与完成

覆盖表按用户任务所需决定逐项记录概念、条件、操作、评价、失败与规范。每项包含已有依据、未核内容、对当前目标的影响、下一动作和当前结论。材料数量与搜索次数用于追踪工作量。

局部调研达到其问题要求后，可交付有范围的设计判断。其它未满足义务保留原状态，返回整套制作档案的实际准备度。找到一个合理解释后，继续检查会改变该解释的重要反例。

## 5. 数值与工具调查

查阅公开案例时区分原报告结果、当前复核与当前生成的数值。若用户要求实际运行基准，使用已有仿真验证规范核对工具、版本、适用范围与输出来源。当前制作活动可以先形成验证计划。

工具调研产出能力—版本—模型—格式—资源—验证缺口矩阵。AI 提议候选工具，用户的既有软件、行业环境和许可约束参与选择。

## 6. 领域经验与公开知识的关系

公开知识可解释或挑战行业经验，行业案例可揭示公开方法遗漏的工况或组织约束。比较时将实际条件与目标展开，保留不同范围内的有效结论。冲突尚未分辨时，围绕会影响当前任务的差异设计最小核查。

用户明确的工作偏好可形成项目操作决定。关于科学机制和方法性能的判断需要对应证据，并以实际验证范围表达。
