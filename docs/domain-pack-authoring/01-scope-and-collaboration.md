# 01 制作目标与协作边界

## 1. 用户要获得的结果

一套领域包应表达用户所处行业怎样定义问题、选择模型、准备输入、使用工具、判断结果、处置失败。经验需保留发生条件、决策理由和证据，通过领域包在后续任务中检索、解释和应用。

一次制作活动可先覆盖狭窄且有价值的任务。目标写明使用者、任务、交付、适用范围、已知资料、资源边界和验收责任。用户可持续补充案例和规则，新内容以修订进入同一制作档案。

制作产物包括以下内容。

- 用户确认的任务范围、关键判断与尚未解决的取舍。
- 原始材料清单、可定位片段、案例复原和口述经验。
- 领域词汇、标签、知识单元、适用条件与证据关系。
- 采用决定、冲突、知识修订、入库和检索核验记录。
- 模型、参数、工作流、工具需求、检查和计量的依据映射。
- 可编辑领域包及范围匹配的验证计划与回执。

## 2. 协作职责

| 职责 | 应执行的动作 | 需要明确来源的判断 |
|---|---|---|
| 用户/领域贡献者 | 说明任务、提供案例与规范、解释隐含条件、纠正提取、选择采用范围 | 经验来自亲历、转述、文件还是尚待验证的判断 |
| AI 引导者 | 读取已有内容、提出有针对性问题、协助结构化、建议标签、查资料、展示差异和缺口 | 抽取、推导、建议与原文陈述各自标记 |
| 领域审阅职责 | 判断科学与行业适用性、规则强度、例外、冲突和评价方法 | 审阅范围、依据、尚不能判断的内容 |
| 包开发职责 | 编写声明、接口和适配实现，连接知识与执行入口 | 哪些能力已实现、哪些需要开发或验证 |

这些职责可由同一用户兼任，用户可明确指定其它审阅者。普通资料整理按当前工作区授权执行。涉及现有仿真独立审查的职责隔离继续沿用其契约。

## 3. 用户决定与协助动作

| 内容 | 默认动作 | 何时请求用户决定 |
|---|---|---|
| 文件名、大小、摘要、导入批次、已有来源身份 | 自动登记并回报 | 路径或资料归属无法确定时 |
| 页码、段落、表格、代码位置与读取覆盖 | 提取并标读取方式 | 关键文字/数值存在OCR或解析歧义时 |
| 术语、主题与已有标签匹配 | 提出建议，可应用用户预先认可的确定性映射 | 新术语、同名异义、领域分类合并或重要语义标签变化时 |
| 经验归纳、适用范围、原因与例外 | 生成候选并引用依据 | 纳入工作知识或调整规则强度前 |
| 行业规范的项目适用性与优先级 | 提取条款和候选判断 | 影响当前任务执行或验收时 |
| 包工作流、关键模型、指标与阈值 | 按已确认决定编写草稿 | 新资料造成实质范围、科学含义或验收变化时 |
| 检索索引、导出、检查与已接受内容的可逆编排 | 在授权范围内完成 | 超出资料使用/分发范围时 |

采用支持逐项、批次和有边界的预先规则。用户已经明确的意见形成决定引用，后续同范围动作直接复用。高后果缺口只影响依赖它的部分，其余资料整理、调研与设计可以继续。

## 4. 完成程度

按目标记录 designReady、knowledgeReady、integrationReady、validatedInScope。每项附范围、证据、缺口和下一动作。资料页数、知识条数或标签数量只用于工作量统计。

设计稿可以先描述尚缺证据的候选路径。将经验用于正式模型选择、强制检查或验收时，应具备对应的采用范围与支持材料。用户可采用一条个人经验供项目提醒，科学证据状态仍按已有验证记录表达。

## 5. 当前决定

本轮用户要求主动引导制作、重点收集领域经验、接收行业案例/规范并打标入库，存储类型保持开放。文档中的会话轮次建议、表单字段和实施切分属于工程细化。各具体领域的规则、行业权威结构及数值阈值在制作会话中依据用户材料形成。
