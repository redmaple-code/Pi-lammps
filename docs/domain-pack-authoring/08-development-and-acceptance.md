# 08 开发实施与验收

## 1. 实现边界

制作工具在现有仿真执行入口旁增加 AuthoringService，通过知识、资料、包解析与运行端口接入。制作会话状态由制作服务维护，仿真阶段状态继续由现有内核维护。界面可先使用对话、表单与差异预览，CLI/TUI/后续界面共享同一业务契约。

| 组件 | 行为 | 交付 |
|---|---|---|
| 会话与引导 | 恢复上下文、缺口排程、问题与回答绑定、批次反馈 | session/activity/question/decision |
| 资料接收 | 版本、解析覆盖、片段和同源关系 | source/fragment/intake batch |
| 标签工作台 | 候选标注、原文对照、用户修改、词汇维护 | taxonomy/annotation revisions |
| 经验整理 | 访谈、案例复原、条款与知识单元 | case/clause/knowledge proposals |
| 调研助手 | 按设计缺口检索、核原文、比较和反证 | research findings 与候选 |
| 采用与仓储 | 决定范围、条件提交、查询、追踪、导出 | store receipts 与有效视图 |
| 包编排 | 知识选择、DesignBinding、声明与开发任务 | draft pack 与影响说明 |
| 验证与维护 | 对话回放、反例、后端契约、应用反馈 | 验收回执与知识修订 |

## 2. 实施工作包

| 编号 | 内容 | 依赖与完成证据 |
|---|---|---|
| DPA-W1 | 记录契约、问答目录、存储能力和适配映射 | Schema/实例/引用与修订语义检查 |
| DPA-W2 | 会话、资料登记、缺口与少量问题引导 | DPA-W1，真实恢复/更正/暂缓路径 |
| DPA-W3 | 片段、标签建议、用户采用和经验访谈 | DPA-W1/2，原文对照、批次修改和版本失配 |
| DPA-W4 | 入库、检索回查、冲突与便携交换 | DPA-W1/3，重复提交、并发及故障恢复 |
| DPA-W5 | 调研、案例/条款与设计绑定 | DPA-W2–4，来源/条件/反例和用户决定链 |
| DPA-W6 | 包编排与端到端制作验证 | DPA-W1–5，两种领域的用户参与回放和采用后效果 |

这些工作包属于后续实施规划。当前交付的机器文件是规范和验证夹具，工具能力按实现记录逐项补齐。

## 3. 验收场景

下表的要求为目标行为。当前产品场景状态为 planned，文档层检查见 evidence 目录。

| ID | 场景与预期 |
|---|---|
| DPA-01 | 已有任务和用户决定的会话恢复后，系统复用已知内容，仅追问当前关键缺口。 |
| DPA-02 | 用户仅能讲亲历经验时，系统登记口述来源并逐步补条件、动作、结果和边界。 |
| DPA-03 | 用户只给一份行业规程时，系统从适用对象和执行场景引导出当前任务。 |
| DPA-04 | 新资料进入候选工作台，登记/解析回执真实反映读取范围与歧义。 |
| DPA-05 | AI 建议的标签和经验归纳保留 suggested/candidate，用户决定覆盖后才按该用途生效。 |
| DPA-06 | 用户批次采用或声明确定性整理规则后，系统应用到明确对象及范围，并保留决定引用。 |
| DPA-07 | 用户更正一个条件后，候选知识、标签和包绑定更新，旧记录与更正轨迹保留。 |
| DPA-08 | 用户不知道或暂缓回答时，保存 gap，继续处理不依赖该回答的活动。 |
| DPA-09 | 同源报告与多个片段保持共同来源身份，独立来源统计可核查。 |
| DPA-10 | 行业术语同名异义时保留语境，标签合并/拆分经采用决定并可追踪旧赋值。 |
| DPA-11 | 标注原文变更或OCR歧义时，定位/摘录核验指出 stale 或待确认位置。 |
| DPA-12 | 用户经验的观察和原因判断分别入库，证据不足的机制保持 unassessed。 |
| DPA-13 | 规范条款保留版本、效力、适用范围，项目采用理由和外部义务属性分别表达。 |
| DPA-14 | 用户采用一条项目实践后，工作检索显示其用途和范围，科学认识状态仍按证据记录。 |
| DPA-15 | 已有经验与新规范冲突时，系统展示双方条件和出处，围绕实际受影响决定追问。 |
| DPA-16 | 缺口调研按任务核查原文/反证，摘要、后续转述与当前归纳的身份可区分。 |
| DPA-17 | 一条被采用经验可回查至来源、片段、标签、决定，并连接具体流程/检查/指标。 |
| DPA-18 | 有意重复 commitChange 时返回原回执，相同操作 ID 异内容被拒绝。 |
| DPA-19 | 并发修改或批次部分写入后，系统保留用户编辑并以提交日志/后端能力对账恢复。 |
| DPA-20 | 检索模型落后时，读侧显示修订状态，按 ID 回查与采用范围校验仍正确。 |
| DPA-21 | 交换包跨后端导入保留来源、标签、条件、决定和修订，能力差异可见。 |
| DPA-22 | 资料使用/导出范围改变后，相应查询、导出和包构建按有效范围执行。 |
| DPA-23 | 小分子对接与有限元动力学使用相同制作协议，领域问题与标签由各自材料形成。 |
| DPA-24 | 应用反馈出现反例时，系统提议收窄或修订范围，用户采用后更新关联包候选。 |

## 4. 实测方法

制作机制用固定输入和反例检查字段、修订、引用、权限范围与恢复。引导效果需真实用户参与，记录反复提问、更正被采纳情况、领域经验覆盖、用户负担和设计改进，不以填写字段数量代替质量。

存储适配用同一逻辑夹具和故障注入评估语义，待选择实际后端时执行其集成测试。真实科研或工程运行另按对应包的科学验收开展。

每条回执含 scenarioId、实现/契约版本、输入修订、环境、用户/审阅角色、观察结果、证据、结论和限制。构造回放注明 demonstration，真实使用注明 userSession，并分别统计。
